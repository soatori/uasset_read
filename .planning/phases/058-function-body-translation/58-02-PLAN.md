# 58-02-PLAN.md — CppFunctionBodyFormatter: CppBodyIR → .cpp 文本

## Objective

创建函数体格式化模块，将 `CppStatement` 树渲染为可读的 C++ .cpp 文件文本。扩展现有 `cpp_header_formatter.py` 的管线，新增 `format_cpp_function_body()` 和 `format_full_cpp_implementation()` 函数。

## Context

Wave 1 产出了 `CppMethodIR.body: List[CppStatement]`。Wave 2 将这些 IR 节点翻译为 .cpp 实现文本。

CONTEXT.md 决策：

## Tasks

### Task 1: format_cpp_function_body — 单函数体渲染

<read_first>
- src/uasset_read/cpp_gen/formatters/cpp_header_formatter.py（现有 format_cpp_call_statements 模式）
- src/uasset_read/cpp_gen/formatters/cpp_json_ir.py（CppMethodIR, CppStatement 系列）
</read_first>

<action>
创建 `src/uasset_read/cpp_gen/formatters/cpp_function_body_formatter.py`，实现：

`format_cpp_function_body(method_ir: CppMethodIR) -> str`

渲染规则：
1. 函数签名行：`{ReturnType} {ClassName}::{MethodName}({Params})`
   - 如果 `is_override` → 不加 override（.cpp 实现不加）
   - 如果 `is_const` → 加 const
2. 函数体大括号包裹
3. 遍历 `method_ir.body` 中的每个 `CppStatement`：
   - `CppCallStmt` → `{target}->{method_name}({args});`（target="Super" 时用 `Super::{method_name}()`）
   - `CppAssignmentStmt` → `{lhs} = {rhs};`
   - `CppIfStmt` → `if ({condition}) {{\n{then_body}\n}}` + else 分支
   - `CppInlineExprStmt` → 不独立成行（仅在其他语句的参数位置使用）
4. 缩进：4 空格
5. 函数之间空 2 行

Super 调用特殊处理：
- 如果 `CppCallStmt.target == "Super"` → 输出 `Super::MethodName();`
- 如果 `CppCallStmt.target_type == "pointer"` 且 target ≠ "Super" → `target->MethodName();`
</action>

<acceptance_criteria>
- format_cpp_function_body 可导入
- 输入含 Jump() 调用的 method_ir → 输出包含 `void AMyCharacter::Jump() { Super::Jump(); }` 格式文本
- 输入含 IfStmt 的 method_ir → 输出包含 `if (condition) { ... }` 格式文本
- 缩进为 4 空格
- Super 调用格式正确（`Super::` 前缀）
</acceptance_criteria>

`format_full_cpp_implementation(ir: CppClassIR) -> str`

- `.cpp` 文件：`format_full_cpp_implementation(ir)`

## must_haves

### truths
- .cpp 输出与 .h 输出配对：同一个 CppClassIR 生成两个文件（D-58-05）
- Super 调用必须使用 `::` 作用域解析符，不是 `->`
- 函数签名与 Phase 57 输出的 CppMethodIR 完全一致（参数名、类型、顺序）
- Pure 函数内联表达式不独立成行，只嵌入到调用语句的参数位置（D-58-04）
- 缩进始终 4 空格，UE 标准风格
- 不生成构造函数代码（那是 Phase 59 的职责）
