<objective>
Fix critical byte swapping bug where UTF-8 string data is incorrectly reversed.

**Root Cause:** FArchive.read() reverses ALL multi-byte reads when byte_swapping=True, but UTF-8 encoding is byte-order independent. Reversing UTF-8 bytes corrupts string data.

**Impact:** Big-endian files have garbage NameMap content (e.g., "TestName" becomes "emanTseT\x00" after reversal).

Purpose: Correct byte swapping to only affect integer/float values, not raw byte reads.
Output: Fixed FArchive with type-specific byte order handling.
</objective>

    ```python
        """Read signed 32-bit integer with proper byte order handling."""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'i', self.read(4))[0]

    def read_u32(self) -> int:
        """Read unsigned 32-bit integer with proper byte order handling."""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'I', self.read(4))[0]

    def read_i64(self) -> int:
        """Read signed 64-bit integer with proper byte order handling."""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'q', self.read(8))[0]

    def read_u64(self) -> int:
        """Read unsigned 64-bit integer with proper byte order handling."""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'Q', self.read(8))[0]

    def read_f32(self) -> float:
        """Read 32-bit float with proper byte order handling."""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'f', self.read(4))[0]
    ```
