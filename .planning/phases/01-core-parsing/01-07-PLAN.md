<objective>
修复 TotalHeaderSize 读取位置 bug，阻止真实 Lyra UE5 文件解析。

**根本原因：** 解析器在文件头末尾读取 TotalHeaderSize（line 514-516），但 UE 源码显示：
- UE 版本 < PACKAGE_SAVED_HASH（UE4）：TotalHeaderSize 在 CustomVersions 后、PackageName 前读取
- UE 版本 >= PACKAGE_SAVED_HASH（UE5）：TotalHeaderSize 在 PackageName 后读取（当前 SavedHash 块）

**影响：** Lyra Character_Default.uasset（legacy=-7, UE4 v521）失败：
- 解析器读取 TotalHeaderSize=14620 作为 PackageName FString length
- 读取 14620 bytes 作为 package_name（整个文件）
- NameOffset 变为垃圾值 589824

**UE 源码参考（PackageFileSummary.cpp lines 254-258）：**
```cpp
// UE4 order（version < PACKAGE_SAVED_HASH）：
// CustomVersions -> TotalHeaderSize -> PackageName -> PackageFlags

// UE5 order（version >= PACKAGE_SAVED_HASH）：
// SavedHash -> TotalHeaderSize -> PackageName -> PackageFlags
```

目的：修正 UE4 和 UE5 文件的 TotalHeaderSize 位置。
输出：修复 read_package_summary()，版本感知 TotalHeaderSize 位置。
</objective>
