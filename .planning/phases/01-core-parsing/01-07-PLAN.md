<objective>
Fix TotalHeaderSize reading position bug preventing real Lyra UE5 file parsing.

**Root Cause:** Parser reads TotalHeaderSize at end of header (line 514-516), but UE source shows:
- UE versions < PACKAGE_SAVED_HASH (UE4): TotalHeaderSize read AFTER CustomVersions, BEFORE PackageName
- UE versions >= PACKAGE_SAVED_HASH (UE5): TotalHeaderSize read AFTER PackageName (current SavedHash block)

**Impact:** Lyra Character_Default.uasset (legacy=-7, UE4 v521) fails:
- Parser reads TotalHeaderSize=14620 as PackageName FString length
- Reads 14620 bytes as package_name (entire file)
- NameOffset becomes garbage value 589824

**UE Source Reference (PackageFileSummary.cpp lines 254-258):**
```cpp
// UE4 order (version < PACKAGE_SAVED_HASH):
// CustomVersions -> TotalHeaderSize -> PackageName -> PackageFlags

// UE5 order (version >= PACKAGE_SAVED_HASH):
// SavedHash -> TotalHeaderSize -> PackageName -> PackageFlags
```

Purpose: Correct TotalHeaderSize position for both UE4 and UE5 files.
Output: Fixed read_package_summary() with version-aware TotalHeaderSize position.
</objective>
