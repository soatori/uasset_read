# Phase 22 Plan 06: 正确定位 pins_offset

## Objective

通过研究 UE 源码中的 UEdGraphNode 序列化结构，正确定位 pins 数组的起始位置，解决 TEST-02/03 失败问题。

**Purpose:** 解决动态扫描方案找到错误位置的问题。
**Output:** pins_offset 正确定位，PinName 解析为有效值，TEST-02/03 通过。

## Problem Analysis (Root Cause)

### 核心问题：动态扫描定位到错误位置

**当前代码问题（uasset_read.py:3091-3116）：**
```python
while archive.tell() < node_export.serial_offset + scan_end:
    test_count = archive.read_i32()
    if 1 <= test_count <= 20:  # 合理的 pins 数量
        test_null = archive.read_i32()
        if test_null == 0:  # bNullPtr == 0 表示有效 pin
            ...
```

**实际数据分析（EnhancedInputActionEvent 节点）：**
- offset 21: count=4, next=268 → 268 != 0，跳过
- offset 33: count=6, next=0 → 被识别为 pins_start，但解析失败

**解析失败原因：**
当使用 offset 33 作为 pins_start 时：
- OwningNode_2 = 0（应为有效引用）
- PinName idx = 0（解析为 name_map[0] = 根包名，而非实际 pin name）

这说明 offset 33 不是正确的 pins 数组起始位置！

### UE 源码分析

**UEdGraphNode::Serialize (EdGraphNode.cpp L212-263)：**
```cpp
void UEdGraphNode::Serialize(FArchive& Ar)
{
    Super::Serialize(Ar);  // UObject::Serialize
    
    #if WITH_EDITOR
    if (Ar.CustomVer(FBlueprintsObjectVersion::GUID) >= FBlueprintsObjectVersion::EdGraphPinOptimized)
    {
        UEdGraphPin::SerializeAsOwningNode(Ar, Pins);
    }
    #endif
}
```

**关键发现：**
1. Pins 序列化在 `#if WITH_EDITOR` 块中
2. 需要版本检查：FBlueprintsObjectVersion >= EdGraphPinOptimized (4)
3. 资产的 FBlueprintsObjectVersion = 121 > 4，满足条件

**SerializeAsOwningNode 结构 (EdGraphPin.cpp L2063-2130)：**
```cpp
void UEdGraphPin::SerializePinArray(FArchive& Ar, TArray<UEdGraphPin*>& ArrayRef, ...)
{
    int32 ArrayNum = NumCurrentEntries;
    Ar << ArrayNum;  // pins_count
    
    for (int32 PinIdx = 0; PinIdx < ArrayNum; ++PinIdx)
    {
        SerializePin(Ar, PinRef, ...);
    }
}

bool SerializePin(FArchive& Ar, ...)
{
    bool bNullPtr = PinRef == nullptr;
    Ar << bNullPtr;  // 第一个字段
    
    if (!bNullPtr)
    {
        Ar << LocalOwningNode;  // OwningNode (SerializePin 部分)
        Ar << PinGuid;          // PinGuid (16 bytes)
        PinRef->Serialize(Ar);  // UEdGraphPin::Serialize
    }
}
```

**UEdGraphPin::Serialize 结构 (EdGraphPin.cpp L1838-1948)：**
```cpp
bool UEdGraphPin::Serialize(FArchive& Ar)
{
    Ar << OwningNode;  // 再次序列化 OwningNode
    Ar << PinId;       // 再次序列化 PinId
    
    Ar << PinName;     // FName (版本依赖)
    Ar << PinFriendlyName; // FText (WITH_EDITORONLY_DATA)
    Ar << SourceIndex;     // int32 (版本依赖)
    Ar << PinToolTip;      // FString
    Ar << Direction;       // uint8
    PinType.Serialize(Ar); // FEdGraphPinType
    Ar << DefaultValue;    // FString
    ...
}
```

**序列化顺序总结：**
1. pins_count (int32)
2. 对每个 pin：
   - bNullPtr (bool, 4 bytes)
   - OwningNode_1 (FPackageIndex, 4 bytes) — SerializePin 前置
   - PinGuid_1 (FGuid, 16 bytes) — SerializePin 前置
   - OwningNode_2 (FPackageIndex) — UEdGraphPin::Serialize 再次序列化
   - PinId_2 (FGuid) — UEdGraphPin::Serialize 再次序列化
   - PinName (FName) + 其他字段

### 数据结构验证

**offset 9-20 的 12 bytes 零值分析：**
```
09: 00 00 00 00 00 00 00 00 00 00 00 00
```
这可能是：
- UObject::Serialize 的剩余字段（引用数组等）
- 或者 Pins 数组前的某种 marker

**假设 offset 21 = pins_count = 4：**
- offset 25: 268 → 这是 bNullPtr? 非零表示 null pin
- offset 29: 0 → 第二个 pin 的 bNullPtr = 0
- offset 33: 6 → OwningNode_1 = 6?

这个解读不正确，因为 6 作为 OwningNode index 值太小（应该指向导出表）。

### 根本原因

**关键问题：UObject::Serialize 的数据未被正确处理**

script_serial_size = 9 bytes 仅标记了部分 UObject 数据。
UEdGraphNode::Serialize 在 Super::Serialize 之后还有：
- WITH_EDITOR 版本检查
- 可能的其他属性数据

**offset 9-20 的 12 bytes 零值是关键：**
这可能是：
1. UObject 基类的某些字段（引用数组、属性列表等）
2. 或者 FBlueprintsObjectVersion 相关的数据

需要研究 UObject::Serialize 的具体字段顺序。

**关键源码路径：**

**预期发现：**
UObject::Serialize 可能包含：
- ObjectFlags 相关字段
- 引用数组（ObjectReferenceArray）
- 属性迭代器数据

根据 ObjectResource.h 注释：
```
ScriptSerializationStartOffset: "offset from the start of the export's serialization data to the start of the portion of this export's data that is serialized using tagged property serialization."
```

这意味着 script_serial_offset 是 tagged property serialization 的起始位置，而不是 UObject::Serialize 的结束位置！

**正确理解：**
- serial_offset: 导出数据起始位置
- serial_size: 导出数据总大小
- script_serial_offset: tagged property serialization 起始（相对于 serial_offset）
- script_serial_size: tagged property serialization 大小

所以数据结构是：
```
[serial_offset]
  [UObject native serialization fields] (非 tagged property)
  [script_serial_offset: tagged property serialization]
    [property 1]
    [property 2]
    ...
  [script_serial_size 结束]
  [UEdGraphNode::Serialize 数据（Pins 等）]
[serial_offset + serial_size]
```
