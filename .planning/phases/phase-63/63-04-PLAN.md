<task type="auto" tdd="true">
  <name>Task 1: FunctionBodyBuilder — label generation and basic assembly</name>
  <files>src/uasset_read/kismet/body_builder.py</files>
  <action>
Create `FunctionBodyBuilder` class in `body_builder.py`:

**`__init__`:** Accept optional `TypeRegistry`. Initialize `_execution_flow_stack` (list for Push/Pop tracking), `_indent_level` (int, starts at 1 for inside function body).

**`build(expressions, signature)`:**
1. Build label map: iterate expressions, for each with `StatementIndex`, map index → label number (`Label_{index}`). Jump targets reference these labels.
2. Collect variable declarations from `type_registry`: for each registered variable, emit `{type} {name};` at top of function body.
3. Iterate expressions with StatementIndex tracking:
   - If StatementIndex is a jump target → emit `Label_{index}:` line
   - Call `line_cpp(expr, type_registry)` to get C++ string
   - If result is non-empty → emit `{"    " * _indent_level}{cpp};`
   - Special: EX_PushExecutionFlow → push address to `_execution_flow_stack`, no output
   - Special: EX_EndOfScript → stop iteration
4. Wrap in function braces:
   ```
   {signature}
   {{
   {declarations}

   {body}
   }}
   ```

**Key details:**
- Use `StatementIndex` as label identifier (matches Phase 62 output)
- Empty `line_cpp()` results (EX_EndOfScript, EX_PushExecutionFlow, etc.) produce no output line
- Indentation: 4 spaces per level, body at level 1
- Execution flow stack: PushExecutionFlow adds address to list, PopExecutionFlow pops and renders goto, PopExecutionFlowIfNot pops and renders conditional goto
- The `_execution_flow_stack` must be reset fresh per `build()` call (no state leakage per RESEARCH.md Pitfall 2)

<task type="auto" tdd="true">
  <name>Task 2: to_function_body() — EX_Return handling and terminator detection</name>
  <files>src/uasset_read/kismet/body_builder.py</files>
  <action>
Enhance `FunctionBodyBuilder.build()` with proper terminator handling:

**EX_Return special handling:**
- When `line_cpp()` returns `"return {expression}"`, render as `return {expression};` (not `return {expression};;`)
- The semicolon should be part of the assembly, not from line_cpp() output

**Terminator detection:**
- Track whether we've seen EX_Return or EX_EndOfScript
- After terminator, skip remaining expressions (they're post-return cleanup)
- Exception: if there are PushExecutionFlow entries before the return, still process them

**Jump-to-return optimization (per CUE4Parse RESEARCH.md line 1470-1479):**
- When processing EX_Jump: check if the target StatementIndex corresponds to an EX_Return expression
- If so, render as `return` instead of `goto Label_X`
- When processing EX_JumpIfNot: same check — if target is EX_Return, render as `if (!condition) return`

**Edge case — multiple returns:**
- Some functions have early returns followed by cleanup code
- Don't skip after first return; instead mark "primary return seen" and continue with reduced processing

**Output verification:**
- Generated body should be syntactically balanced (matching braces)
- Every label referenced by goto should have a corresponding `Label_X:` marker
- Last statement should be a return (if function has return value)
