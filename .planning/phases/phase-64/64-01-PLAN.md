```python
import json

@dataclass
class KismetDecompiledResult:
    """Single function decompilation result (D-04)."""
    function_name: str                    # e.g. "ExecuteUbergraph_MyBP"
    signature: str                         # e.g. "void ExecuteUbergraph_MyBP(int32 EntryPoint)"
    local_variables: list[dict]            # [{name, type}, ...] from TypeRegistry snapshot
    cpp_code: str                          # C++ pseudocode string (multi-line, indented)
    expressions: list                      # raw KismetExpression list for debugging

    def to_dict(self) -> dict:
        """JSON-serializable dict. expressions serialized via their to_dict() if available."""
        return {
            "function_name": self.function_name,
            "signature": self.signature,
            "local_variables": self.local_variables,
            "cpp_code": self.cpp_code,
            "expressions": [e.to_dict() if hasattr(e, 'to_dict') else str(e) for e in self.expressions],
        }

    def to_json(self, indent: int = 2) -> str:
        """JSON string view (D-08)."""
        return json.dumps(self.to_dict(), indent=indent)

    def to_cpp_string(self) -> str:
        """C++ pseudocode string view (D-08). Returns cpp_code directly."""
        return self.cpp_code
```

Key decisions:
- `expressions` field stores raw list for debugging; `to_dict()` serializes each via its own `to_dict()` if available, else falls back to `str()`
- `local_variables` is `list[dict]` (each dict has `name` and `type` keys) — snapshot from TypeRegistry after translation
- Follow existing `@dataclass` + `to_dict()` pattern from models/result.py
