**目标**: 使解析器能够输出足够的结构信息，支持 Blueprint → C++ 代码翻译。

## Gap 分析

对比 `BP_FirstPersonCharacter.uasset` 解析结果与等价的 C++ 实现 (`FirstPersonCCharacter.cpp/h`)，
识别出以下无法自动化翻译的部分：

| # | Gap | 影响 | 严重程度 |
|---|-----|------|---------|
| G1 | `linked_to_raw` 全为空数组 | 执行流/数据流/连接全部为 0 | P0 |
| G2 | 组件属性值未提取（位置/旋转/缩放/布尔标志） | C++ 构造函数数值不可见 | P0 |

| G6 | UPROPERTY/UFUNCTION 元数据（Category/可见性）不可提取 | C++ 宏修饰符无法推断 | P2 |

## Phase 47: Pin LinkedTo 修复

**Goal:** `linked_to_raw` 从空数组变为实际 Pin 引用列表，`connections > 0`，`execution_flows` 中 `nodes` 非空。

**根因分析:**
当前解析器在 `read_ue_graph_node()` 中读取 pins 数组时，`read_ue_graph_pin()` 虽然解析了 `LinkedTo`
数组（`read_pin_array`），但数据最终进入了 `linked_to_raw` 字段。问题在于 `read_ue_graph()` 中当
`nodes_count == 0`（UE5 典型情况）时，节点通过 `outer_index` 收集，但每个节点的 `script_serial_offset`
和 `script_serial_size` 来自 ObjectExport 表头。UE5 的 UEdGraphNode 序列化格式可能已变更，导致
pins 数组的实际读取位置与预期不一致。

**具体任务:**
- 在 `read_ue_graph_node()` 中添加二进制位置追踪，确认 `LinkedTo` 数组是否被正确消费
- 验证 `read_pin_array()` 返回非空数组时数据是否正确传递到 `UEdGraphPin.linked_to_raw`
- 修复序列化偏移计算，确保每个 pin 的 `linked_to_raw` 包含实际 Pin 引用
- 以 `BP_FirstPersonCharacter.uasset` 为测试资产，验证 EventGraph 的 connections > 0

**验证:**
- `uasset-read --json --graph` 输出中 `connections` 数组非空
- `execution_flows` 中至少一条 flow 的 `nodes` 数组非空
- 执行流匹配 C++ 逻辑：`InputAction.Triggered → CallFunction(AddControllerYawInput)`

## Phase 48: 组件属性递归解析

**Goal:** 输出组件的数值型属性（位置、旋转、缩放、布尔标志），与 C++ 构造函数中的配置对应。

**具体任务:**
- 在 `blueprint/` 中新增 `component_parser.py`，遍历 ExportMap 中的组件类型对象
- 解析组件的 PropertyTag 序列，提取嵌套结构体值：
  - `RelativeLocation` / `RelativeRotation` / `RelativeScale3D` → FVector/FRotator
  - `CapsuleRadius` / `CapsuleHalfHeight` → float
  - `bOnlyOwnerSee` / `bUsePawnControlRotation` → bool
  - `FieldOfView` / `FirstPersonScale` → float
- 在 JSON 输出的 `blueprint` 部分新增 `components` 数组
- 每个组件包含：名称、类型、父组件、属性值字典

**验证:**
- JSON 输出包含 `components` 数组，至少 2 个组件（FirstPersonMesh, FirstPersonCamera）
- `FirstPersonCameraComponent` 包含 `RelativeLocation=(-2.8, 5.89, 0.0)` 等数值
- `CharacterMovementComponent` 包含 `AirControl=0.5` 等数值

## Phase 49: 函数调用引脚解析

**Goal:** K2Node_CallFunction 节点的功能签名（参数名、类型、方向）完整提取。

**具体任务:**
- 在 `read_ue_graph_node()` 中，确保 CallFunction 节点的 pins 数组正确解析
- 从 pin 的 `pin_type.pin_category` 和 `pin_subcategory` 推断参数类型：
  - `exec` → 执行引脚（无类型）
  - `real` → float
  - `struct` + `Vector` → FVector
  - `object` + `Class` → UObject 派生
  - `wildcard` → 泛型/可变参数
- 区分 input pin（direction=0, exec 除外）和 output pin（direction=1）
- 在 `format_node_dict()` 中输出 `parameters` 数组
- 利用 linker 解析 `function_reference.member_parent` 为具体类名

**验证:**
- CallFunction 节点输出类似 `"parameters": [{"name": "Yaw", "type": "float", "direction": "input"}]`
- `DoAim(Yaw:float, Pitch:float)` 函数签名可识别
- `DoMove(Right:float, Forward:float)` 函数签名可识别

## Phase 50: EnhancedInput 语义增强

**Goal:** K2Node_EnhancedInputAction 节点的触发事件类型（Started/Completed/Triggered）可识别。

**具体任务:**
- 扩展 `read_k2node_enhanced_input()` 读取额外字段：
  - `InputTriggerType` 枚举值（Started/Ongoing/Completed/Triggered）
  - `bIsTriggered` 布尔标志
- 在 pin 级别，识别 exec output pin 的触发事件标签
  - UE5 EnhancedInput 节点有多个 exec output（Started, Triggered, Completed）
  - 每个 exec pin 需要关联到对应的 ETriggerEvent 枚举值
- 在 JSON 输出中标注每个 EnhancedInputAction 的触发类型映射
- 新增 `input_bindings` 数组，格式类似 C++ 的 `BindAction` 调用

**验证:**
- JSON 输出中 `input_bindings` 包含：
  - `JumpAction → Started → DoJumpStart`
  - `JumpAction → Completed → DoJumpEnd`
  - `MoveAction → Triggered → MoveInput`
  - `LookAction → Triggered → LookInput`
- 与 C++ `SetupPlayerInputComponent()` 中的 BindAction 一一对应

## Phase 51: C++ 代码生成器

**Goal:** 基于修复后的 JSON 输出，生成 .h/.cpp 骨架代码。

**具体任务:**
- 新增 `formatters/cpp_formatter.py`
- 从 `blueprint.components` 生成 UPROPERTY 组件声明
- 从 `blueprint.variables` 生成 UPROPERTY 变量声明
- 从 `input_bindings` 生成 SetupPlayerInputComponent 实现
- 从 `graphs[].execution_flows` 生成函数调用体
- 从 `components` 属性生成构造函数初始化代码
- 命令行入口：`uasset-read --cpp file.uasset`

**输出示例:**
```cpp
// .h
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category="Components")
USkeletalMeshComponent* FirstPersonMesh;

UFUNCTION(BlueprintCallable, Category="Input")
void DoAim(float Yaw, float Pitch);

// .cpp
void AFirstPersonCharacter::SetupPlayerInputComponent(UInputComponent* InputComponent) {
    if (UEnhancedInputComponent* EnhancedInputComponent = Cast<UEnhancedInputComponent>(PlayerInputComponent)) {
        EnhancedInputComponent->BindAction(JumpAction, ETriggerEvent::Started, this, &AFirstPersonCharacter::DoJumpStart);
        EnhancedInputComponent->BindAction(MoveAction, ETriggerEvent::Triggered, this, &AFirstPersonCharacter::MoveInput);
    }
}
```

**验证:**
- `uasset-read --cpp BP_FirstPersonCharacter.uasset` 输出 .h/.cpp
- 生成的代码包含所有组件、变量、输入绑定、函数声明
- 生成的代码可编译（需手动补充头文件和少量细节）
