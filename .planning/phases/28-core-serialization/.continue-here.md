## 🎯 Critical Discovery — Root Cause Found!

### UE5 节点序列化格式变化

**问题现象：**
- 9个 K2Node_CallFunction 节点解析失败，回退到 `node_data=dict`
- 错误：`UTF-16 string length 1011044606 too large`
- FunctionReference 解析正确但最终输出缺少 `function_reference`

**根因定位：**
UE5 将 `NodePosX`, `NodePosY`, `NodeGuid` 等字段作为 **PropertyTags** 存储在 `script_serial` 区域，而非 pins 解析后的裸 i32 字段。

**证据：**
```
Export #31: K2Node_CallFunction_8428
script_serial PropertyTags:
  Tag #0: FunctionReference (StructProperty, 66 bytes) ✓ 解析正确
  Tag #1: NodePosX (IntProperty, 4 bytes)    ← UE5 格式！
  Tag #2: NodePosY (IntProperty, 4 bytes)    ← UE5 格式！
  Tag #3: ErrorType (IntProperty, 4 bytes)
  Tag #4: NodeGuid (StructProperty, 16 bytes) ← UE5 格式！
  Tag #5: None

代码错误：pins解析后尝试读取 NodePosX (裸i32)
实际位置：pins后读到的是 Pin 数据残留 → UTF-16 错误
```

### 修复方案

修改 `read_ue_graph_node` 函数（`uasset_read.py:4032-4238`）：

1. **在 script_serial PropertyTags 循环中提取 NodePosX/NodePosY/NodeGuid**
   - 当 `tag.name == "NodePosX"` 时读取 i32 值
   - 当 `tag.name == "NodePosY"` 时读取 i32 值
   - 当 `tag.name == "NodeGuid"` 时读取 16 bytes

2. **删除 pins 解析后的重复读取逻辑**
   - 移除行 4229-4235：`node_pos_x = archive.read_i32()` 等
   - 使用 PropertyTags 提取的值设置这些字段

3. **NodeComment 可能也需类似处理**
   - 检查是否在 PropertyTags 中有 NodeComment tag
