Create the `cpp_gen` module directory and implement `cpp_type_mapper.py` per D-03 (mixed strategy — core hardcoded dict + extensible script path).

**Module structure:**

1. **`UE_TO_CPP_TYPE_MAP`** — hardcoded dictionary mapping UE type paths to C++ types. Cover at minimum:
   - ScriptStruct types: `"/Script/CoreUObject.Vector"` → `"FVector"`, `"/Script/CoreUObject.Rotator"` → `"FRotator"`, `"/Script/CoreUObject.Transform"` → `"FTransform"`, `"/Script/CoreUObject.Vector2D"` → `"FVector2D"`, `"/Script/CoreUObject.LinearColor"` → `"FLinearColor"`, `"/Script/CoreUObject.Name"` → `"FName"`, `"/Script/CoreUObject.Text"` → `"FText"`, `"/Script/CoreUObject.String"` → `"FString"`, `"/Script/CoreUObject.Guid"` → `"FGuid"`
   - Class types: `"/Script/Engine.SceneComponent"` → `"USceneComponent"`, `"/Script/Engine.ActorComponent"` → `"UActorComponent"`, `"/Script/Engine.Character"` → `"ACharacter"`, `"/Script/Engine.Pawn"` → `"APawn"`, `"/Script/Engine.GameModeBase"` → `"AGameModeBase"`, `"/Script/Engine.Controller"` → `"UController"`
   - Primitive types: `"float"` → `"float"`, `"double"` → `"double"`, `"bool"` → `"bool"`, `"int"` → `"int32"`, `"int64"` → `"int64"`, `"byte"` → `"uint8"`, `"name"` → `"FName"`, `"text"` → `"FText"`, `"string"` → `"FString"`

2. **`ENGINE_CLASS_PATHS`** — dictionary mapping `/Script/Engine.XXX` paths to C++ class names. Keys: `"/Script/Engine.Character"` → `"ACharacter"`, `"/Script/Engine.Pawn"` → `"APawn"`, `"/Script/Engine.Actor"` → `"AActor"`, `"/Script/Engine.GameModeBase"` → `"AGameModeBase"`, etc. This supports D-02 inheritance chain resolution. Use UE naming convention rules: `A` for Actors, `U` for UObject/UComponent, `F` for Structs, `E` for Enums.

3. **`ue_path_to_cpp_type(ue_type: str) -> str`** — main conversion function:
   - Input formats: `"ScriptStruct'CoreUObject.Vector'"`, `"Class'Engine.SceneComponent'"`, `"float"`, `"bool"`, `"name"`, `"text"`, etc.
   - First try exact match in `UE_TO_CPP_TYPE_MAP`
   - If input contains `'` (quoted format like `ScriptStruct'...'`), extract the inner path and try mapping
   - If still not found, apply heuristic: extract class name from path and prefix with U/A/F/E based on UE convention
   - Fallback: return the input as-is with a warning log (use Python `logging` module)

4. **`ue_package_path_to_cpp_class(package_path: str) -> str`** — for D-02 inheritance chain:
   - Input: `"/Script/Engine.Character"`, `"/Script/Engine.Pawn"`
   - Look up in `ENGINE_CLASS_PATHS`
   - If not found, extract the last segment and apply prefix heuristic (A for Engine classes that are Actors, U for Components, etc.)
   - Return C++ class name like `"ACharacter"`, `"APawn"`

Follow the existing codebase patterns: use `from __future__ import annotations`, type hints, docstrings. No runtime dependencies beyond Python stdlib. Use `logging.getLogger(__name__)` for warnings, not `print`.

Then update `src/uasset_read/cpp_gen/__init__.py` to export `ue_path_to_cpp_type` and `ue_package_path_to_cpp_class`.

   - `CPF_EditAnywhere` → `"EditAnywhere"`

   - `CPF_BlueprintReadOnly` → `"BlueprintReadOnly"`

   - `CPF_InstancedReference` → `"Instanced"`

   - `CPF_BlueprintCallable` → `"BlueprintCallable"`
   - `CPF_Replicated` → `"Replicated"`
   - `CPF_Net` → `"Net"` (only if CPF_Replicated not also set — CPF_Replicated implies CPF_Net)
   - `CPF_Transient` → `"Transient"`
   - `CPF_DuplicateTransient` → `"DuplicateTransient"`
   - `CPF_Config` → `"Config"`

   - Iterate through `CPF_TO_UPROPERTY_MAP` in order
   - For combined checks (CPF_Edit | CPF_BlueprintVisible), check if both bits are set
   - For single flag checks, use bitwise AND
   - Skip duplicate marks (if EditAnywhere already added from combined check, skip standalone CPF_EditAnywhere)
   - For components: always add `"VisibleAnywhere"` and `"BlueprintReadOnly"` as defaults if no explicit visibility flags set (this matches UE's SCS component default behavior)
   - Return sorted/ordered list of UPROPERTY mark strings
