在 `read_ue_graph_pin` 中修复 DefaultTextValue 的 FText 读取。

**方案：使用与 PinFriendlyName 相同的容错策略。**

当前 PinFriendlyName（L319-325）使用 try/except + seek-back，但 read_ftext_with_history
内部已经处理了容错。问题是 DefaultTextValue 在 try 块外读了 flags 和 history_type，
当 read_ftext_with_history 内部因 FString 长度异常失败时，seek-back 到了 flags 之前的位置，
而不是 history_type 之后的正确位置。

修复：对 DefaultTextValue 使用与 PinFriendlyName 相同的模式：

```python
# 12. DefaultTextValue (FText) — 修复：使用 read_ftext_with_history + seek-back
dtext_start_pos = archive.tell()
try:
    _dtext_flags = archive.read_i32()
    _dtext_history = archive.read_u8()
    # 在 UE5 中，某些 FText 可能使用不同的序列化格式
    # 对异常长度使用容错跳过
    read_ftext_with_history(archive, _dtext_history, tolerant=True)
except Exception as e:
    if DEBUG_PIN_PARSING:
        print(f"[DEBUG FTEXT] DefaultTextValue error: {e}")
    archive.seek(dtext_start_pos)
```

**但关键问题是**：`read_ftext_with_history` 内部的 `_read_fstring_safe` 会抛出异常
（当长度 > 10000 时），这个异常会被外层的 except 捕获并 seek-back。
而 seek-back 到的 `dtext_start_pos` 是 flags 之前的位置，不是 FText 之后的位置。

**正确修复**：在 `read_ftext_with_history` 内部容错时，不要抛出异常，
而是静默跳过异常 FString。或者，对 DefaultTextValue 使用更激进的容错：

```python
# 12. DefaultTextValue (FText)
dtext_start_pos = archive.tell()
try:
    _dtext_flags = archive.read_i32()
    _dtext_history = archive.read_u8()
    # UE5 容错：如果 history_type 导致的 FText 读取失败，
    # 尝试直接读一个 FString 作为 fallback（某些 UE5 格式使用简化 FText）
    if _dtext_history == 0xFF:
        pass  # None type, nothing to read
    elif _dtext_history == 0:
        # Base: Namespace + Key + SourceString
        for _ in range(3):
            _read_ftext_fstring(archive)
    else:
        # Custom: up to 5 FStrings
        for _ in range(5):
            _read_ftext_fstring(archive)
except Exception:
    archive.seek(dtext_start_pos)
```

其中 `_read_ftext_fstring` 是一个新的 helper：
```python
def _read_ftext_fstring(archive: FArchive) -> str:
    """读取 FText 内部的 FString，对异常长度使用容错。"""
    length = archive.read_i32()
    if length == 0:
        return ""
    if abs(length) > 10_000:
        # 异常长度，不回退（消费已读取的 i32），返回空字符串
        return ""
    if length < 0:
        data = archive.read(-length * 2)
        return data.decode('utf-16', errors='replace').rstrip('\x00')
    data = archive.read(length)
    return data.decode('utf-8', errors='replace').rstrip('\x00')
```

**这个 helper 与 `_read_fstring_safe` 的关键区别**：
- `_read_fstring_safe` 在长度异常时会 `archive.seek(archive.tell() - 4)` 回退
- `_read_ftext_fstring` 不回退，直接返回空字符串（已消费了 i32 长度字段）
- 这样确保 FText 内部的每个 FString 即使长度异常，位置也不会错位
