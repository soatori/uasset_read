# Plan 72-01: Pin 连接修复

## Objective

修复 Phase 72-A 诊断确认的 2 个 Pin 序列化 bug，确保 UEdGraphPin 二进制解析正确。

## Tasks

### Task 1: history_type signed 转换

**位置:** `graph.py` L398, L449

**问题:** `archive.read_u8()` 返回 255（UE 意图是 -1/None），`read_ftext_with_history` 检查 `255 in range(-1,11)` → FALSE → 位置不变 → 后续字段全部错位。

**修复:** 在入口处添加 signed 转换：
```python
history_type = archive.read_u8()
if history_type >= 128:
    history_type -= 256
```

影响行：
- L398: PinFriendlyName FText 的 history_type
- L449: DefaultTextValue FText 的 history_type

### Task 2: ParentPin 条件读取

**位置:** `graph.py` L476-479

**问题:** 当前代码无论 `null != 0` 都读取 24 字节（4+4+16），但 UE 序列化中 `null != 0` 时只存在 8 字节（4+4），多读的 16 字节 GUID 导致 RefPassThrough/PersistentGuid/BitField 全部错位。

**修复:** 条件读取：`null != 0` 时只读 8B, `null == 0` 时读 24B。

### Task 3: 验证测试

运行现有测试套件确认无回归。

## Acceptance Criteria

1. `read_ue_graph_pin` 正确解析 history_type=-1 (0xFF) 为 None
2. ParentPin 在 null!=0 时只消费 8 字节
3. 全部测试通过
