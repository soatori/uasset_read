# Phase 78 Plan 03 — CUE4Parse 架构收敛

## Objective

把 `COR-04` 从“独立 archive + preload 安全”扩展成完整的 **CUE4Parse 风格 Package-centered 收敛计划**：

1. graph / blueprint / pin 解析统一走 linker-aware 主路径  
2. `PackageLinker` 增加 provider/resolver 边界，为跨包 import 解析预留稳定接口  
3. `/Script/` import 明确采用占位符策略  
4. 为 Phase 79 的 `DefaultFileProvider` / IoStore 接入建立不返工的接口面

## Why This Plan Exists

现有计划只覆盖了：

- `78-01`: UObject 层次与 SuperField
- `78-02`: archive 隔离、preload 安全

但仍缺少 CUE4Parse 架构里真正决定 linker 稳定性的部分：

- graph 单一路径
- provider-aware import resolution
- `/Script/` 占位符
- 传统 `FPackageIndex` 与未来 IoStore 索引抽象的边界

如果这些不先落进计划，Phase 79 做 `IFileProvider` / IoStore 时会再次改 `parse_uasset.py`、`graph/parser.py`、`linker.py` 的主调用链。

## Scope

### A. Graph / Blueprint 管线收敛

- `parse_uasset_with_linker()` 必须先建 linker，再进入 graph / metadata / kismet 后处理
- `parse_uasset_with_linker()` 中的 graph 提取必须显式传递 linker
- `extract_blueprint_graphs()` 增加 linker-aware 路径，避免长期仅调用无 linker `read_ue_graph()`
- `read_ue_graph()` / `read_ue_graph_node()` / `read_ue_graph_pin()` 的 linker 模式变为主路径，而不是附加兼容入口

### B. Provider / Resolver 接口预留

- 在 `link/linker.py` 定义最小 resolver 接口，例如：
  - `resolve_external_import(import_obj) -> Optional[UObjectInstance | ExternalObjectRef]`
  - `resolve_script_import(import_obj) -> ExternalObjectRef`
- 当前默认实现可返回占位符或 `None`，但调用链必须稳定
- Phase 79 的 `DefaultFileProvider` 通过这个接口接入，不再改 graph / metadata 解析层

### C. `/Script/` 占位符策略

- 明确：不尝试真实加载 `/Script/Engine`、`/Script/CoreUObject` 包
- 解析结果以 metadata / placeholder 形式返回
- 类名解析保持稳定，不把“是否能加载真实脚本包”变成 graph 解析成败条件

### D. Result / Traceability

- `LinkerParseResult` 增加与 provider-aware 解析对应的状态字段或便捷访问器
- 计划和索引文件显式记录：
  - 本包解析完成
  - 跨包解析接口已定
  - IoStore 尚未落地但接口已保留

## Tasks

### Task 1 — Linker 入口主路径收敛

**Files:** `parse_uasset.py`, `tests/test_linker_entry_pipeline.py`

**Changes**

- `parse_uasset_with_linker()` 中 linker 创建先于 export property 主解析
- linker 模式下 export property 读取由 `preload()` 驱动
- `preload_all=True` 仅作为 eager compatibility 开关

**Done when**

- linker 入口不存在“先无 linker 解析一轮，再补 linker”的主路径
- `_post_process()` 在 linker 模式下不依赖预先填满的 `export.properties`

### Task 2 — Graph 主路径收敛

**Files:** `parse_uasset.py`, `graph/parser.py`, `serializers/graph.py`, `tests/test_linker_graph_pipeline.py`

**Changes**

- `_post_process()` 在 linker 模式下调用 `extract_blueprint_graphs(..., linker=linker)`
- `graph/parser.py` 新增可选 `linker` 参数，并在 linker 存在时传给 `read_ue_graph()`
- 以 linker-aware 调用为主，兼容无 linker 路径仅保留给 `parse_uasset()`

**Done when**

- `parse_uasset_with_linker()` 的 graph / pin / metadata 不再依赖“先无 linker 解析，后补 linker”
- `linked_to_objects` / `parent_pin_object` / `default_object_ref` 在 linker 路径下通过统一入口建立

### Task 3 — Provider / Resolver 边界

**Files:** `link/linker.py`, `serializers/object_resources.py`, `file_provider/__init__.py`, `tests/test_linker_provider_interface.py`

**Changes**

- 新增最小 provider 协议或抽象类型，不要求 Phase 78 就实现完整目录扫描
- `PackageLinker.resolve_package_index()` 保持本包解析职责
- `resolve_import()` 或等效 helper 增加外部解析挂点，默认返回占位符/空
- `object_resources` 的类名/父类名解析在 linker 模式下优先使用该接口

**Done when**

- 当前不需要真实跨包加载也能稳定运行
- Phase 79 可以在不改 graph / blueprint 主逻辑的前提下接上 `DefaultFileProvider`

### Task 4 — `/Script/` 占位符与结果建模

**Files:** `link/linker.py`, `link/result.py`

**Changes**

- 增加 script import placeholder 表达
- 结果对象可区分：
  - 本包 export
  - 本包 import
  - script placeholder
  - unresolved external import

**Done when**

- `/Script/` import 不触发真实加载
- 类名/outer/super 解析可稳定返回 metadata
