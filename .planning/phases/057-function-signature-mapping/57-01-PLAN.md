  <action>
Add three new dataclasses to cpp_json_ir.py after the CppProperty class, following the same @dataclass + to_dict() pattern:

1. **CppCallParameter** — single parameter in a method/call signature:
   - `name: str` — sanitized C++ identifier (e.g., "LeftRight" not "Left / Right")
   - `cpp_type: str` — C++ type with direction applied (e.g., "const FString&", "double", "FVector")
   - `direction: str` — "input" | "output" | "return"

2. **CppMethodIR** — blueprint function → C++ method declaration (per D-57-02):
   - `cpp_name: str` — C++ function name (sanitized, e.g., "PrimaryThumbstick")
   - `return_type: str` — C++ return type (default "void")
   - `parameters: List[CppCallParameter]` — parameter list
   - `ufunction_specifiers: List[str]` — UFUNCTION macro marks (e.g., ["BlueprintCallable"], ["BlueprintPure"], [])
   - `is_override: bool` — True for K2Node_Event with bOverrideFunction=True (per D-57-04)
   - `is_const: bool = False` — const method modifier (Phase 58 context, default False)
   - `source_node_type: str = ""` — "K2Node_FunctionEntry" | "K2Node_Event" | "" for traceability
   - `to_dict(self) -> Dict[str, Any]` — serialization method matching CppProperty pattern

3. **CppCallStatement** — K2Node_CallFunction → C++ call statement (per D-57-02):
   - `method_name: str` — called method name
   - `target: str` — call target ("this" or variable name)
   - `target_type: str = "pointer"` — "this" | "pointer" (controls -> vs ->)
   - `args: List[str]` — argument name list (sanitized identifiers, Phase 57 only extracts names not values)
   - `is_self_context: bool = True` — from FMemberReference.b_self_context
   - `to_dict(self) -> Dict[str, Any]` — serialization method

Also update `CppClassIR.methods` type annotation from `List[Any]` to `List["CppMethodIR"]`.
