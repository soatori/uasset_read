## 二、序列化层问题 (Phase 67 覆盖范围)

### 2.1 FString 解析异常 — 35 处

**状态:** Phase 67 已修复底层逻辑，但此文件仍有 35 条 warning

| 类型 | 数量 | null 比例 | 位置范围 |
|------|------|-----------|---------|
| UTF-16 (100% null) | 25 处 | 100% | pos 93381 ~ 135421 |
| UTF-16 (50% null) | 3 处 | 50% | pos 109356, 113388, 117415, 121442 |
| UTF-8 (51.6%~62.5% null) | 7 处 | 51.6%~62.5% | pos 109450, 113482, 117509, 121536, 121932, 125011, 126893 |

**根因分析:** 这些位置对应属性值中的 FName 索引区域。UE 序列化中 FName 使用 `int32 index + int32 number` 格式，不是 FString。解析器在某些属性类型中将 FName 区域误作 FString 读取，导致读到索引整数对应的字节模式，产生大量 null 字节。

**影响:** 部分属性值（尤其是 FName 类型的字段如 Socket 名称、Collision Profile、组件名称）被解析为空字符串，但不阻塞管线。

**对应 C++ 字段:**
- `FName("head")` — 相机挂载点 Socket
- `FName("NoCollision")` — Collision Profile
- `FName("First Person Mesh")` — 组件名称
- `EFirstPersonPrimitiveType::FirstPerson` — 枚举值

## 七、结论

**结构提取层面:** 解析器成功提取了 BP_FirstPersonCharacter.uasset 的完整结构——69 个 Export 对象、4 个 Blueprint Graph、6 个组件、11 个变量、73 个 Import、21 个软引用。与 C++ 源码对照，所有组件和 Input Actions 均能一一对应，覆盖率 100%。

**功能还原层面:** 由于 **Pin 连接数据完全丢失**（所有 `linked_to_raw` 和 `linked_to_objects` 为空），执行流和数据流不可还原。虽然能识别到 `AddControllerYawInput`、`AddMovementInput`、`Jump` 等函数调用节点存在，但无法确认它们之间的连接关系和执行顺序。**实际功能逻辑不可还原。**

**v12.0 评估:** v12.0 的 P68-71 交付物（节点注册表、处理器架构、N2CStruct、链式表达）在**节点级**表现正确，但均依赖 Pin 连接数据才能发挥价值。P67 的序列化修复使管线能跑通，但 FName/FString 区分仍有 35 处遗漏。

**下一步优先级:**
1. **修复 Pin 连接序列化** — 这是解锁功能还原的 P0 前提
2. **修复 FName/FString 区分** — 消除 35 条字符串丢失
3. **Kismet 反编译** — 获取字节码级逻辑（独立于 Pin 连接的另一条路径）
