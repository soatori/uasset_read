# v7.0 UE 加载方式对齐 — 对象图重建

**日期：** 2026-05-14
**状态：** 规划完成，待执行

---

## 1. 问题背景

v6.0 完成了模块化重构，但解析模式仍是**直接字节读取**：
- FArchive 顺序 seek/read，序列化器从已知偏移读取字段
- 对象引用（PackageIndex）仅解析为名字字符串，不是实际对象
- 无对象图概念，数据扁平化为 dataclass
- Outer 树（Package → Class → Properties 层级）未构建

**v6.0 Phase 35e 失败教训**: 试图通过字节级偏移修正解决 linked_to_raw 为空问题，偏离了根本方向。真正的问题不是"差几个字节"，而是当前架构缺少 UE 编辑器的对象图重建机制。

---

## 2. 目标架构

### 2.1 当前架构

```
文件 → FArchive(字节) → Serializers → 扁平数据
                                ↓
                    PackageIndex → 名字字符串
```

### 2.2 目标架构

```
文件 → FArchive(字节) → PackageLinker → UObjectInstance 对象图
                          ↑ 调用现有序列化器
                                ↓
                    PackageIndex → UObjectInstance 实际对象引用
```

---

## 3. UE FLinkerLoad 参考

UE 编辑器的 FLinkerLoad 采用两阶段加载：

| UE FLinkerLoad | PackageLinker 对应 |
|---|---|
| `Link()` | `link()` — 读头信息，创建 UObjectInstance 壳 |
| `CreateExport()` | 内部壳创建（在 link() 中） |
| `Preload(Index)` | `preload(index)` — 延迟反序列化属性 |
| `ImportMap` | `_import_objects` (UObjectInstance 列表) |
| `ExportMap` | `_export_objects` (UObjectInstance 列表) |
| `LinkerRoot` | `_root_objects` |
| `IndexToObject(FPackageIndex)` | `resolve_package_index(pkg_idx)` |

## 5. 设计原则

1. **不修改现有序列化器** — PackageLinker 坐于现有序列化器之上，复用它们
2. **增量采用** — 新增并行入口点，现有代码路径不变
3. **延迟加载** — preload(index) 按需反序列化，不一性加载
4. **零回归** — 现有测试必须全部通过

---

## 6. 与 v6.0 的关系

| v6.0 | v7.0 |
|------|------|
| 直接字节读取 | UE 加载方式对齐 |
| PackageIndex → 名字 | PackageIndex → 对象引用 |
| 扁平数据 | 对象图 |
| 无 Outer 树 | Outer 树可导航 |

v7.0 不破坏 v6.0 的任何功能，而是建立并行层，增量引入对象图能力。
