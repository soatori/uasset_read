## 失败原因

Phase 35-35e（Pin Offset 根因诊断）执行严重偏离目标：

1. **字节对齐问题复杂度高**：UE5 蓝图 Pin 序列化涉及多个版本阈值（FrameworkVersion、MainstreamVersion、ReleaseVersion、UE4Version、UE5Version），每个阈值影响不同字段的序列化格式

2. **文档与实际不符**：多个版本的阈值判断逻辑交叉，导致代码分支选择错误。例如 `file_version_ue4=522` 超过阈值 324，但实际字节结构与预期分支不符

3. **调试方法偏离**：反复尝试字节追踪而非直接查阅 UE C++ 源码中的精确版本阈值逻辑

4. **修复引入新问题**：每次局部修复导致其他测试失败，陷入修复循环

## 遗留问题

### Phase 35e 未解决

1. `linked_to_raw` 始终为空或包含垃圾数据
2. `data_flows` 和 `execution_flows` 无法正确构建
3. PayloadTocOffset 解析错误（独立 bug）

### 根本原因分析

UE5 资产 (`file_version_ue4=522, file_version_ue5=1017`) 的 `FEdGraphPinType` 序列化：

- 预期：使用"默认反射序列化"分支（UE4 < 324）
- 实际：阈值判断使用 UE4 版本，导致进入"自定义序列化"分支
- 需要查阅 UE C++ `EdGraphPin.cpp` L163-346 确认正确的版本阈值逻辑
