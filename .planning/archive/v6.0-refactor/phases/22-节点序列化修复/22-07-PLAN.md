# Phase 22 Plan 07: Direction 和 PinType 序列化格式修复

## 目标

修复 UEdGraphPin 序列化中 Direction 字段后的 2 bytes 额外数据问题，使 TEST-02/03/04 通过验证。

## 背景

Phase 22-06 发现的问题：
- PinToolTip 实测 6 bytes（预期 4 bytes，空字符串）
- Direction 后有 2 bytes 额外数据（00 00）
- PinCategory 位置偏移了 2 bytes，导致读取垃圾值

根因分析（22-07-RESEARCH.md）：
- UE 源码验证 Direction 为 TEnumAsByte<uint8>（1 byte）
- PinToolTip 为 FString（空字符串 4 bytes）
- 实测数据与源码不一致

### Task 2: 实现 PinToolTip 读取修复

**目标**: 修复 PinToolTip 的读取逻辑，正确处理可能的额外字节

**步骤**:
1. 记录读取前的位置
2. 使用标准方式读取 FString
3. 验证后续数据，检测是否有额外的 padding

**实验优先级**:
1. 优先级 1: 读取标准 FString（4 bytes length + data）
2. 如果后续 PinCategory index 不合理，尝试跳过 1-2 bytes padding

**代码修改**:
```python
def read_ue_graph_pin(...) -> UEdGraphPin:
    # ... 前面的代码 ...

    # 6. PinToolTip (FString) [L1870]
    pin_tooltip_start = archive.tell()
    try:
        pin_tooltip = archive.read_fstring()
        logger.debug(f"PinToolTip: '{pin_tooltip}' at offset {pin_tooltip_start}")

        # 验证后续位置是否正确
        next_pos = archive.tell()
        logger.debug(f"After PinToolTip: position {next_pos}")

        # 预读下一个 PinCategory index，验证是否合理
        peek_index = archive.peek_i32()
        logger.debug(f"Peek PinCategory index: {peek_index}")

        if peek_index < 0 or peek_index >= len(name_map):
            # 可能存在 padding，尝试跳过
            logger.warning(f"PinCategory index {peek_index} invalid, checking for padding...")

            # 尝试跳过 1 byte
            archive.seek(next_pos)
            archive.read_u8()
            peek_index = archive.peek_i32()
            logger.debug(f"After skipping 1 byte, Peek index: {peek_index}")

            if peek_index < 0 or peek_index >= len(name_map):
                # 尝试跳过 2 bytes
                archive.seek(next_pos)
                archive.read_u16()
                peek_index = archive.peek_i32()
                logger.debug(f"After skipping 2 bytes, Peek index: {peek_index}")

                if peek_index < 0 or peek_index >= len(name_map):
                    # 仍然无效，恢复原始位置
                    logger.error("Failed to find valid PinCategory position, restoring")
                    archive.seek(pin_tooltip_start)
                    pin_tooltip = archive.read_fstring()

    except Exception as e:
        logger.error(f"PinToolTip 读取失败: {e}")
        archive.seek(pin_tooltip_start)
        pin_tooltip = archive.read_fstring()
```

**验证标准**:
- PinToolTip 正确读取（空字符串 → ""）
- Direction 位置正确
- PinCategory index 正确（148 → "exec"）

def read_ed_graph_pin_type(archive, name_map, summary):
    pin_type = FEdGraphPinType()

    # 1-2. PinCategory and PinSubCategory (version dependent)
    # 添加自动修正逻辑
    start_pos = archive.tell()
    valid_category = False

    # 尝试多种偏移
    for skip_bytes in [0, 1, 2]:
        try:
            archive.seek(start_pos + skip_bytes)

            if use_fname_format:
                pin_type.pin_category = archive.read_name(name_map)
                pin_type.pin_sub_category = archive.read_name(name_map)
            else:
                pin_type.pin_category = archive.read_fstring()
                pin_type.pin_sub_category = archive.read_fstring()

            # 验证 PinCategory 是否有效
            if (pin_type.pin_category is not None and
                len(pin_type.pin_category) > 0 and
                pin_type.pin_category in name_map):

                valid_category = True
                if skip_bytes > 0:
                    logger.warning(f"PinCategory valid after skipping {skip_bytes} bytes")

                # 继续读取后续字段
                pin_type.pin_sub_category_object = archive.read_i32()
                # ... 其他字段 ...
                break

        except Exception as e:
            logger.debug(f"Failed with skip_bytes={skip_bytes}: {e}")
            continue

    if not valid_category:
        logger.error("Failed to read valid PinCategory, using fallback")
        archive.seek(start_pos)
        # 使用原始逻辑

    return pin_type

3. **向后兼容**: 修复可能影响其他 UE 版本的解析
   - **缓解**: 使用版本检测，对不同版本使用不同的逻辑
