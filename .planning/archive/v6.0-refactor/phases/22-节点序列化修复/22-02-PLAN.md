# Phase 22 Plan 02: 修复 PinFriendlyName (FText) 跳过逻辑

## Objective

修复 `read_ue_graph_pin` 未正确跳过 EditorOnly 字段 PinFriendlyName (FText) 的问题，解决 PinToolTip 解析位置偏移。

**Purpose:** 使 Pin 数据解析位置正确，后续字段（PinToolTip、Direction 等）能正确读取。
**Output:** 正确解析的 Pin 数据，TEST-02/03/04 通过验证。

## Problem Analysis

### ISSUE-02: PinToolTip 解析位置偏移

**根因确认:**
- 当前代码 `uasset_read.py:2846-2847` 有注释 "PinFriendlyName (FText) - EditorOnly，跳过"
- **但没有实际代码跳过 FText 格式数据！**
- UE 源码 `EdGraphPin.cpp:1858-1863`：
  ```cpp
  #if WITH_EDITORONLY_DATA
  if (!Ar.IsFilterEditorOnly())
  {
      Ar << PinFriendlyName;  // FText 序列化
  }
  #endif
  ```
- 对于 editor-saved (uncooked) 赞产，`Ar.IsFilterEditorOnly()` 返回 false，PinFriendlyName 被序列化

**FText 序列化格式 (Text.cpp:850-1043):**
```
1. Flags (int32)
2. HistoryType (int8) - 决定后续数据类型
3. 根据 HistoryType:
   - None (0): bHasCultureInvariantString (bool) + [CultureInvariantString (FString)]
   - Base (1): Namespace (FString) + Key (FString) + SourceString (FString)
   - 其他类型有各自格式
```

**影响:** PinToolTip 读取位置错误 → Direction、PinType 等后续字段全部偏移

### ISSUE-03: K2Node 数量不匹配

**现状:** 解析 10 个节点，导出表 30 个节点

**根因分析:**
- `uasset_read.py:3358-3360`: `except ParseError: pass` 静默跳过失败节点
- ISSUE-02 导致 Pin 解析失败 → 部分节点被跳过

**预期:** 修复 ISSUE-02 后，节点解析数量应恢复正常

```python
def skip_ftext_editoronly(archive: FArchive) -> None:
    """
    跳过 EditorOnly FText 字段（如 PinFriendlyName）。
    
    FText 序列化格式（Text.cpp:850-1043）：
    1. Flags (int32)
    2. HistoryType (int8) - ETextHistoryType 枚举
    3. 根据 HistoryType 类型：
       - None (0): bHasCultureInvariantString (bool/uint8) + [CultureInvariantString (FString)]
       - Base (1): Namespace (FString) + Key (FString) + SourceString (FString)
       - NamedFormat/OrderedFormat/ArgumentFormat 等类型有各自格式
       - 对于简单跳过，只需处理常见类型
    
    Args:
        archive: FArchive positioned at FText start
    """
    # 1. Flags (int32)
    flags = archive.read_i32()
    
    # 2. HistoryType (int8)
    history_type = archive.read_u8()
    
    # 3. 根据 HistoryType 跳过后续数据
    # ETextHistoryType 枚举值：
    # None = 0, Base = 1, NamedFormat = 2, OrderedFormat = 3, 
    # ArgumentFormat = 4, AsNumber = 5, AsPercent = 6, AsCurrency = 7,
    # AsDate = 8, AsTime = 9, AsDateTime = 10, Transform = 11, StringTableEntry = 12
    
    if history_type == 0:  # None
        # bHasCultureInvariantString (bool 序列化为 uint8)
        b_has_culture_invariant = archive.read_u8()
        if b_has_culture_invariant != 0:
            # CultureInvariantString (FString)
            archive.read_fstring()
    elif history_type == 1:  # Base
        # Namespace (FString) + Key (FString) + SourceString (FString)
        archive.read_fstring()  # Namespace
        archive.read_fstring()  # Key
        archive.read_fstring()  # SourceString
    elif history_type >= 2 and history_type <= 12:
        # 其他类型的通用跳过策略：读取 FString 直到遇到边界
        # NamedFormat: SourceFmt + Arguments map
        # OrderedFormat: SourceFmt + Arguments array
        # 简化处理：读取若干 FString
        # 根据实际测试数据调整
        try:
            # 尝试读取最多 5 个 FString（覆盖大多数类型）
            for _ in range(5):
                archive.read_fstring()
        except Exception:
            # 跳过失败时回退：尝试定位下一个已知字段
            pass
    else:
        # 未知的 HistoryType，记录警告但继续
        # 可能需要调整位置
        pass
```

关键要点：
- FText 格式基于 HistoryType 决定后续数据
- None (0) 和 Base (1) 是最常见类型
- 其他类型需根据实际数据调整
</action>

- 函数对 None (0) 和 Base (1) 类型有明确的跳过逻辑
