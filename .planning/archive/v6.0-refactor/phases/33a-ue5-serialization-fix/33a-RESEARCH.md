# Phase 33a: UE5 序列化问题修复 - Research

**Researched:** 2026-05-12
**Domain:** UE5.0 序列化格式、PropertyTag 体积验证、FText history_type
**Confidence:** MEDIUM-HIGH (基于 bp_firstperson_output.json 错误分析)

## Summary

Phase 33a 专注于修复从 UE5.0 蓝图文件 `BP_FirstPersonCharacter.uasset` 中发现的三个已知错误。这些错误不是语法错误，而是 **序列化格式兼容性问题**：

1. **FText 大小异常** - read_fstring 读取到 33554432 字符长度（0x02000000）
2. **PropertyTag Size 为负数** - 0xBFC00000（浮点数 -1.5 的位模式）
3. **数组大小超出文件边界** - 3328 bytes > 2300 bytes remaining

这三个错误**共享同一个根本原因**：某个前置字段的解析偏移不正确，导致后续所有字段的偏移都错位。Phase 33a 的任务是定位并修复这个偏移错位问题。

**关键假设：** 这些错误不是数据损坏，而是 UE5.0 序列化格式的未知变更。

### Pattern 1: FText 历史类型解析

**What:** UE5 的 FText 有多种 history_type，每种结构不同
**When to use:** 读取 PinFriendlyName, DefaultTextValue, AutogeneratedDefaultValue

```python
from typing import Tuple, Union

def read_ftext_with_history(archive, history_type: int) -> Tuple[str, int]:
    """
    读取 FText，返回 (值, 消耗字节数)
    
    history_type:
    - 0xFF (-1 as unsigned): None (无历史，仅 flags)
    - 0 (Base): Namespace + Key + SourceString
    - 1-254: Custom (5 FString 历史)
    """
    consumed = 0
    
    if history_type == 0xFF:
        # None 类型：读取 flags
        b_has_culture = archive.read_bool()
        consumed += 1  # flags
        if b_has_culture:
            culture = archive.read_fstring()
            consumed += 4 + len(culture) * 2 + 2  # length + string + null
        return "", consumed
    
    elif history_type == 0:
        # Base 类型：Namespace + Key + SourceString
        namespace = archive.read_fstring()
        key = archive.read_fstring()
        source_string = archive.read_fstring()
        consumed += 4 + len(namespace) * 2 + 2
        consumed += 4 + len(key) * 2 + 2
        consumed += 4 + len(source_string) * 2 + 2
        return source_string, consumed
    
    else:
        # Custom 类型：5 个 FString 历史
        for i in range(5):
            try:
                archive.read_fstring()
            except Exception:
                break
        return "", consumed

def read_fstring_safe(archive) -> str:
    """容错版本的 read_fstring，对异常长度返回空字符串"""
    try:
        return archive.read_fstring()
    except ParseError as e:
        # 记录警告但返回空字符串
        return ""
```

### Pattern 2: PropertyTag Size 验证容错

**What:** 对异常大小的 PropertyTag 采用容错策略
**When to use:** 读取 PropertyTag.size 时

```python
def validate_property_tag_size(size: int, remaining: int, context: str,=read_as_warning: bool = False) -> int:
    """
    验证 PropertyTag.size，对异常值采用容错策略
    
    Args:
        size: 读取到的大小
        remaining: 文件剩余字节数
        context: 错误上下文
        read_as_warning: 如果为 True，对大小异常的字段标记为 Warning
    
    Returns:
        实际应读取的字节数（容错模式下可能小于 size）
    """
    # 负数检查
    if size < 0:
        if read_as_warning:
            return 0  # 标记为 Warning，跳过此字段
        else:
            raise ParseError(f"Invalid size {size} (negative) at {context}")
    
    # 边界检查
    if size > remaining:
        if read_as_warning:
            return remaining  # 读取剩余所有字节
        else:
            raise ParseError(f"Size {size} exceeds remaining {remaining} bytes at {context}")
    
    # 合理性检查（对 Warning 类型跳过）
    max_reasonable = max(1024, min(remaining // 10, 100 * 1024 * 1024))
    if size > max_reasonable:
        if read_as_warning:
            return max_reasonable  # 限制为 max_reasonable
        else:
            raise ParseError(f"Size {size} exceeds max_reasonable {max_reasonable} at {context}")
    
    return size
```

### Pattern 3: 节点序列化偏移校验

**What:** 验证节点序列化后的偏移是否与_SERIAL_SIZE 一致
**When to use:** 读取完节点的 script_serial 后

```python
def validate_node_serialization_offset(archive, node_name: str, expected_size: int, actual_read: int):
    """
    验证节点序列化偏移，对不一致的情况采用容错策略
    
    Args:
        archive: FArchive 实例
        node_name: 节点名称（用于错误信息）
        expected_size: PropertyTag.size 或 SerialSize
        actual_read: 实际读取的字节数
    """
    delta = actual_read - expected_size
    
    if delta == 0:
        return  # 完全匹配，无问题
    
    if abs(delta) < 16:
        # 偏差很小（<16 字节），可能是对齐差异，记录警告
        print(f"[WARNING] Node {node_name}: serialization offset delta={delta} (acceptable)")
        return
    
    # 偏差较大，记录详细信息用于调试
    print(f"[ERROR] Node {node_name}: serialization offset delta={delta}")
    print(f"  expected_size={expected_size}, actual_read={actual_read}")
    print(f"  current_position={archive.tell()}")
```

```python
"""UE5 序列化调试工具 - 记录 PropertyTag 读取的详细信息"""

import json
from pathlib import Path

from uasset_read import parse_uasset
from uasset_read.archive import FArchive
from uasset_read.serializers.property_tags import read_property_tag


def debug_property_tag_stream(file_path: str):
    """调试 PropertyTag 读取流"""
    archive = FArchive(file_path)
    summary = # ... read_package_summary(archive)
    name_map = # ... read_name_table(archive, summary)
    
    results = []
    
    for export_idx, export in enumerate(export_map):
        if export.script_serial_size == 0:
            continue
        
        script_start = export.serial_offset + export.script_serial_offset
        script_end = script_start + export.script_serial_size
        
        archive.seek(script_start)
        
        while archive.tell() < script_end:
            start_pos = archive.tell()
            tag = read_property_tag(archive, name_map, summary.legacy_file_version, summary.file_version_ue5)
            end_pos = archive.tell()
            
            results.append({
                "export_index": export_idx,
                "export_name": export.object_name,
                "tag_name": tag.name,
                "tag_type": tag.type,
                "offset": start_pos,
                "size": tag.size,
                "read_bytes": end_pos - start_pos,
                "position_after": end_pos,
            })
            
            if tag.name == "None":
                break
    
    archive.close()
    
    # 输出到 debug_output_v2.json
    output_path = Path(file_path).stem + "_debug_v2.json"
    with open(output_path, 'w', encoding='utf-8') as f:
        json.dump(results, f, indent=2, ensure_ascii=False)
    
    print(f"Debug output written to {output_path}")
    return results


if __name__ == "__main__":
    import sys
    if len(sys.argv) < 2:
```

## Parse Error Analysis

### Error #1: CategoryName Size 3328 > 2300

**Context:** SCS_Node_1 Export #1577058304

**Observation:**
```
- Name: CategoryName
  Type: Warning
  Value: ParseError: Cannot read 3328 bytes at position 136084, only 2300 bytes remaining
```

**Analysis:**
- Type 是 `Warning`（非正常类型），表示此处有问题
- 位置 `136084` (0x2128C)
- 剩余 `2300` 字节
- 文件总大小约 `138384` 字节 (136084 + 2300)

**Hypothesis:**
1. CategoryName 的 size 字段被错误解释（如 int32 vs int64）
2. 前置字段（如 BoolProperty）读取错误，导致偏移错位
3. UE5.0 在 SCS_Node 中添加了额外的字段

**Verification Plan:**
```python
# 在 debug 工具中
```

### Error #2: RelativeLocation Size -1067974656

**Context:** CharacterMesh0 Export #3224633344

**Observation:**
```
- Name: RelativeLocation
  Type: Warning
  Value: ParseError: Invalid size -1067974656 (negative) at ...
```

**Hex Analysis:**
```
-1067974656 = 0xBFC00000 (as unsigned: 0xBFC00000)
 IEEE 754 float: -1.5 (exact!)
```

**Hypothesis:**
- 某个字段被错误读取为 RelativeLocation 的 size
- 这个字段的实际值是 -1.5 (浮点数)

**Candidate Fields:**
1.SocketName 或 AttachToName (FString) — 长度可能是 -1.5 的位模式
2.未对齐的 BoolProperty — 读取为 float 后得到 -1.5
3.节点 Guid 错误读取 — 某个 16 字节字段被解释为单个 float

**Verification Plan:**
```python
# 检查浮点数 0xBFC00000
import struct
value = struct.unpack('<f', struct.pack('<I', 0xBFC00000))[0]
print(value)  # -1.5
```

**Root Cause Hypothesis:**
某个前置字段（如 SocketName）的 FString 长度被错误读取，导致后续字段偏移错位。

### Error #3: DefaultTextValue Length 33554432

**Context:** K2Node_CallFunction_8428 Pin #3

**Observation:**
```
12. DefaultTextValue: ERROR (UTF-16 string length 33554432 too large)
```

**Hex Analysis:**
```
33554432 = 0x02000000
```

**Hypothesis:**
- DefaultTextValue 的长度字段未正确初始化
- 或者是某种标记值（0x02000000 = 32MB，可能是"未设置"的占位符）

**UE5.0 FText Format:**
```
FText serialization (simplified):
- Flags (i32): 0 or 0x80000000
- HistoryType (u8): 0xFF (None), 0 (Base), or 1-254 (Custom)
- History: N/A, 3 FStrings, or 5 FStrings
```

**Verification Plan:**
检查 history_type 是否为 0xFF (None)，如果是，跳过后续 FString 读取。
