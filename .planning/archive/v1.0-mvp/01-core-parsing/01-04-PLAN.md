<objective>
修复关键的字节交换 bug，UTF-8 字符串数据被错误反转。

**根本原因：** FArchive.read() 在 byte_swapping=True 时反转所有多字节读取，但 UTF-8 编码与字节序无关。反转 UTF-8 bytes 会损坏字符串数据。

**影响：** 大端序文件的 NameMap 内容为垃圾值（例如 "TestName" 反转后变成 "emanTseT\x00"）。

目的：修正字节交换仅影响整数/浮点值，不影响原始字节读取。
输出：修复后的 FArchive，含类型特定字节序处理。
</objective>

    ```python
        """基础读取方法 - 原始字节读取不进行字节交换。"""
        current_pos = self.tell()
        remaining = self._file_size - current_pos
        if size > remaining:
            raise ParseError(
    ```

    ```python
    def read_i32(self) -> int:
        """读取有符号 32 位整数，正确处理字节序。"""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'i', self.read(4))[0]

    def read_u32(self) -> int:
        """读取无符号 32 位整数，正确处理字节序。"""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'I', self.read(4))[0]

    def read_i64(self) -> int:
        """读取有符号 64 位整数，正确处理字节序。"""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'q', self.read(8))[0]

    def read_u64(self) -> int:
        """读取无符号 64 位整数，正确处理字节序。"""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'Q', self.read(8))[0]

    def read_f32(self) -> float:
        """读取 32 位浮点数，正确处理字节序。"""
        fmt = '>' if self._byte_swapping else '<'
        return struct.unpack(fmt + 'f', self.read(4))[0]
    ```
