# 58-01-PLAN.md — CppFunctionBodyExtractor: 执行流/数据流 → CppBodyIR

## Objective

创建核心提取模块，从 `execution_flows` 和 `data_flows` 数据中提取函数体逻辑，生成中间 IR 结构 `CppBodyIR`（包含 `CppStatement` 子类树）。

## Context

Phase 58 依赖 Phase 57 的 `CppMethodIR`（已有 `cpp_name`, `parameters`, `return_type`, `ufunction_specifiers`）和 v9.0 的 `execution_flows` / `data_flows` 输出。

CONTEXT.md 决策：
- D-58-01：执行流从 `then` exec pin 链顺序生成 C++ 语句
- D-58-02：Pure 函数 → C++ 表达式，优先内联
- D-58-03：CallFunction 节点 → C++ 调用语句
- D-58-04：Pure 函数单一使用者内联，多使用者中间变量
- D-58-06：EnhancedInput 事件输出翻译为函数体

### Task 2: extract_function_body — 执行流翻译

<read_first>
- src/uasset_read/graph/flow_builder.py（_trace_execution_from_event, _find_next_exec_node）

</read_first>

<action>
创建 `src/uasset_read/cpp_gen/extractors/cpp_function_body_extractor.py`，实现核心函数：

`extract_function_body(method_ir: CppMethodIR, execution_flow: Dict, data_flows: List[Dict], node_lookup: Dict) -> List[CppStatement]`

逻辑：
1. 遍历 `execution_flow["nodes"]` 列表
2. 对 `K2Node_CallFunction` 节点：
   - 有 exec pin → `CppCallStmt(target, method_name, args)`
   - 无 exec pin（pure）→ 根据 D-58-04 判断内联或中间变量
3. 对 `K2Node_IfThenElse` 等控制流节点 → `CppIfStmt`（条件从 pin 默认值推导）
4. 参数名从 `method_ir.parameters` 和 `data_flows` 的 `data_sources` 映射
5. 跳过 `exec`/`then` pin 本身（不对应语句）

参数推导规则（D-58-03）：
- `real`/`double` 类型 pin → 从 data_flows 追踪源 pin 名
- `bool` 类型 pin → 从 pin default_value 或 data_flows 推导
- `struct`/`object` 类型 pin → 从 self pin 的 PinSubCategoryObject 推导
</action>

<acceptance_criteria>
- extract_function_body 函数存在并可导入
- 输入 Jump 函数的 execution_flow（单个 CallFunction: Jump），返回 [CppCallStmt(method_name="Jump", target="Super")]
- 输入 Aim 函数的 execution_flow（含 CallFunction: AddControllerYawInput(Yaw)），返回对应 CppCallStmt
- 纯函数节点被标记为 is_pure=True
- 控制流节点生成 CppIfStmt
</acceptance_criteria>

### Task 3: Pure 函数内联决策

<read_first>
- src/uasset_read/cpp_gen/formatters/cpp_json_ir.py（CppMethodIR, CppCallStatement）
- src/uasset_read/graph/flow_builder.py（_trace_data_source, is_boundary_node）
- CONTEXT.md D-58-04 决策
</read_first>

<action>
在 `cpp_function_body_extractor.py` 中实现 `_decide_pure_inline()` 函数：

1. 输入：pure CallFunction 节点 + data_flows
2. 查找该节点的 output pin 在 data_flows 中的目标数量
3. 单一目标 → 返回 `CppInlineExprStmt(expression)`，表达式从函数名和参数构建
4. 多目标 → 返回 `CppAssignmentStmt(lhs=temp_var, rhs=expression, cpp_type=return_type)`
5. 内联表达式构建规则：
   - `GetActorRightVector()` → `"GetActorRightVector()"`
   - `Multiply_VectorFloat(Vector, Float)` → `"Vector * Float"`（UE 数学运算内联）
   - 其他 pure 函数 → `"FunctionName(arg1, arg2)"`

常见 UE pure 函数映射表：
```python
PURE_FUNCTION_INLINE_MAP = {
    "Multiply_VectorFloat": lambda a, b: f"{a} * {b}",
    "Add_VectorVector": lambda a, b: f"{a} + {b}",
    "Subtract_VectorVector": lambda a, b: f"{a} - {b}",
    "Multiply_FloatFloat": lambda a, b: f"{a} * {b}",
    # 默认 fallback
    "DEFAULT": lambda name, args: f"{name}({', '.join(args)})",
}
```
</action>

<acceptance_criteria>
- _decide_pure_inline 对单一使用者的 pure 函数返回 CppInlineExprStmt
- _decide_pure_inline 对多使用者的 pure 函数返回 CppAssignmentStmt
- Multiply_VectorFloat 内联为 "vec * scale" 格式
- 非映射函数 fallback 为 "FunctionName(args)" 格式
</acceptance_criteria>

- 执行流顺序严格遵循 `execution_flows[nodes]` 列表顺序（D-58-01）
