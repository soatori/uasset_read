**Key facts:**
- `function_name` only appears on CallFunction/FunctionEntry nodes, NOT universally
- `node_type` is raw class_name (e.g. "K2Node_CallFunction"), NOT semantic type
- `pure` flag is set by checking for exec pin (L560), not from Processor
- ControlFlow nodes have `branch_type` + `stopped_at` and TERMINATE the chain (L587-595)

实现 `to_n2c_json()` 函数，签名：

```python
def to_n2c_json(
    graphs: list[UEdGraph] | None = None,
    result: ParseResult | None = None,
) -> dict:
    """将图数据转换为 N2CStruct 格式 dict。

    参数二选一：graphs 直接传图列表，或 result 传 ParseResult。
    """
```

**转换流程：**

1. **遍历所有 graph.nodes**，使用 N2CIdMapper 为非 Knot 节点分配短 ID
   - Knot 节点（class_name 包含 "Knot"）跳过注册，不分配 ID

2. **构建 N2CNode 列表**（每个非 Knot 节点）：
   - `id`: N2CIdMapper.to_short(node_guid)
   - `type`: N2CNodeTypeRegistry.get_instance().resolve(node.class_name).value（如 "CallFunction"）
   - `name`: _derive_node_name(node, idx)（复用 flow_builder.py L78-83）
   - `comment`: node.node_comment
   - `pure`: 检测无 exec pin（any pin with pin_category == "exec"）
   - `latent`: 从 N2CNodeDefinition.extra_data 的 latent 字段（需调用 Processor）
   - `input_pins`/`output_pins`: 从 node.pins 构建 N2CPin 列表
   - `extra_data`: 调用 Processor 填充 definition，然后从 extra_data 提取：
     - CallFunction: member_name, member_parent, pure, latent
     - Event: event_name, event_parent
     - VariableGet/Set: variable_name, direction
     - Cast: target_type
     - FlowControl: branch_type

3. **构建 flows**：
   - execution: 调用 `extract_chains(build_execution_flows(graph), id_mapper, node_lookup)`
   - data: 调用 `extract_data_flow_map(build_data_flows(graph), id_mapper, node_name_lookup, pin_position_map)`
   - **构建 pin_position_map**: `{(node.node_guid, pin.pin_name): index for node in graph.nodes for index, pin in enumerate(node.pins)}`
   - **构建 node_name_to_guid 反向映射**: `{_derive_node_name(node, idx): node.node_guid for idx, node in enumerate(graph.nodes)}`，传入 flow_extractor 用于 source/target 的 node_name → GUID 反查

4. **metadata 提取**：
   - `Name`: result.summary.package_name（如有 result）
   - `BlueprintType`: result.blueprint.blueprint_type（如有 result.blueprint）
   - `BlueprintClass`: result.blueprint.parent_class（如有 result.blueprint）
   - 无 result 时使用默认值

5. **返回** N2CStruct(**...).to_dict()

**N2CPin 构建规则**（从 UEdGraphPin → N2CPin）：
- `pin_name`: pin.pin_name
- `pin_category`: pin.pin_type.pin_category if pin.pin_type else ""
- `pin_subcategory`: pin.pin_type.pin_subcategory if pin.pin_type else ""
- `direction`: "input" if pin.direction == 0 else "output"
- `default_value`: pin.default_value

**不修改 format_graphs_json()** — 向后兼容。to_n2c_json() 是新增独立入口。

### `extract_chains(execution_flows: list[dict], id_mapper: N2CIdMapper, node_lookup: dict) -> list`

将 build_execution_flows() 的输出转换为 N2C 链式字符串。

**输入形状**（build_execution_flows 实际返回）：
```python
[{
  "start_event": "Event.ReceiveBeginPlay",
  "nodes": [
    {"node_guid": "GUID-A", "node_type": "K2Node_CallFunction", "function_name": "PrintString", ...},
    {"node_guid": "GUID-B", "node_type": "K2Node_IfThenElse", "branch_type": "Branch", "stopped_at": "control_flow_node", ...},
  ]
}]
```

**输出**：
- 线性流 → `["N1->N2->N3"]`
- 分支流（ControlFlow 节点）→ `["N1->N2", "N1->N3"]`（Branch 拆分为两条链）
- 环检测 → fallback 到 pair format: `[{"from": "N1", "to": "N2"}, ...]` + `"_format": "pairs"`

**关键逻辑：**
1. 对每个 execution_flow entry，遍历 nodes 数组
2. 跳过 `node_guid` 为 None 的节点（`"warning": "missing node_guid"` 条目，不含有效 GUID）
3. 对有效节点使用 `id_mapper.to_short(node_guid)` 转换 GUID → 短 ID
3. ControlFlow 节点（branch_type 存在）是链的终点（stopped_at），但需要拆分分支
   - Branch: 拆分为 True/False 两条链（需要查找分支出口连接的实际节点）
   - Sequence/DoOnce 等: 单链终止于此
4. **Knot 穿透**：nodes 中如果出现 Knot 节点（理论上 build_execution_flows 不应包含，因为 exec pin 追踪跳过无 exec pin 的节点），直接跳过
5. **环检测**：使用 DFS 检测 node_guid 序列中的环，MAX_CHAIN_DEPTH=1000

**辅助函数 `_detect_cycle(adjacency: dict[str, list[str]]) -> bool`**：DFS 环检测。

### `extract_data_flow_map(data_flows: list[dict], id_mapper: N2CIdMapper, node_name_to_guid: dict, pin_position_map: dict) -> dict[str, str]`

将 build_data_flows() 的输出转换为紧凑映射。

**输入形状**（build_data_flows 实际返回）：
```python
[{
  "source": {"node": "K2Node_Event_0", "pin": "ReturnValue"},
  "target": {"node": "K2Node_CallFunction_3", "pin": "InString"}
}]
```

**输出**：`{"N1.P0": "N2.P1"}`

**关键逻辑：**
1. source/target 使用 format_pin_ref 输出，mode="name" 时为 `{"node": node_name, "pin": pin_name}`
2. 使用 `node_name_to_guid[node_name]` 反查 GUID（由 to_n2c_json 调用方构建后传入）
3. 然后用 `id_mapper.to_short(guid)` 获取短 ID
4. Pin 索引使用 pin_position_map: `(node_guid, pin_name) → pin_index`
5. 最终格式: `"N{short_id}.P{pin_index}"`
6. 如果 node_name 不在 node_name_to_guid 中（lookup failure），跳过该 data_flow 条目

**pin_position_map 构建**（由 to_n2c_json 调用方构建后传入）：
```python
{(node_guid, pin_name): index for node in graph.nodes for index, pin in enumerate(node.pins)}
```
