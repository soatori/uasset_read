# Phase 73 修复计划

## 目标

Phase 73 聚焦一个主问题：`read_ue_graph_pin()` 在 LinkedTo 前的字段边界仍会错位，导致 `read_pin_array()` 在错误位置读取 count。修复策略是先建立字段级反馈回路，再按证据修复 FText、PinReference、LinkedTo 恢复和 PropertyTag 级联问题。

## 非目标

- 不继续把 `read_fstring()` 截断逻辑包装成根因修复。
- 不用更大的盲扫窗口替代格式校验。
- 不在 Phase 73 内重构整个节点处理器架构。

## Wave 0: 建立反馈回路

**目标:** 让每个失败 Pin 都能输出字段级 offset、消费字节、候选值和失败原因。

**改动范围:**

- `temp/phase73_pin_trace.py`
- `src/uasset_read/serializers/graph.py`
- `tests/test_phase73_pin_trace.py`

**任务:**

1. 新增 `temp/phase73_pin_trace.py`，输入资产路径和可选 graph/node/pin 过滤条件，输出 JSONL 诊断记录。
2. 在 `read_ue_graph_pin()` 周围增加可关闭的诊断钩子，记录：
   - `pin_start_pos`
   - owning node / pin guid / pin name
   - PinFriendlyName、SourceIndex、PinToolTip、PinType、DefaultValue、DefaultObject、DefaultTextValue、LinkedTo 的 start/end
   - 每个字段是否异常、是否回退、是否消费未知字节
3. 诊断日志统一使用 `[P73-PINTRACE]` 前缀，阶段完成前移除或默认关闭。
4. 创建最小测试，验证诊断模式不会改变正常解析结果。

**验收:**

- 能定位 EventGraph 中第一个 LinkedTo 失败 Pin 的 LinkedTo 前字段。
- 诊断脚本输出可被排序和聚合，能统计每类失败的数量。

## Wave 1: 修复 DefaultTextValue/FText 消费语义

**目标:** FText 容错失败时要么完整消费已知格式，要么回退到调用前位置，不能在未知格式下半消费后继续读 LinkedTo。

**改动范围:**

- `src/uasset_read/serializers/graph.py`
- `tests/test_phase73_ftext_boundary.py`

**任务:**

1. 审计 `read_ftext_with_history()` 的 tolerant 分支：
   - 无效 history type 不消费 body。
   - 未支持 history type 不猜测跳过。
   - 解析异常时必须回退到 FText body 起点，除非能证明 fallback target 是格式边界。
2. 在 `read_ue_graph_pin()` 读取 `DefaultTextValue` 时记录 `dtv_start_pos`。失败时回退到 `dtv_start_pos`，再尝试使用 LinkedTo 候选验证决定是否跳过 FText。
3. 增加 `peek_valid_pin_array_count()` 辅助函数，只读不移动指针，用于判断当前位置是否已经是 LinkedTo。
4. 为 history type `-1/0/1` 添加最小二进制测试，验证消费字节精确。

**验收:**

- DefaultTextValue 失败不会把 archive 留在未知位置。
- LinkedTo 前 offset 在失败 Pin 上不再出现不可解释的大跳跃。

## Wave 2: 强化 PinReference 和 LinkedTo 恢复校验

**目标:** `read_pin_array()` 只在候选数组具有可信 PinReference 结构时恢复，避免把随机 count=0 误判为成功。

**改动范围:**

- `src/uasset_read/serializers/graph.py`
- `tests/test_phase73_linkedto_recovery.py`

**任务:**

1. 提取 `validate_pin_reference_at(pos)`：
   - 校验 null marker 语义。
   - 校验 owning_node index 在 import/export 合理范围内。
   - 校验 GUID 非全零或符合 ParentPin 空引用规则。
   - 校验候选引用消费长度与后续字段能衔接。
2. 修改 `_recover_pin_array_count()`：
   - count=0 不能单独作为成功条件。
   - count>0 必须验证全部或至少前两个 PinReference。
   - 恢复成功返回结构化结果：`count`, `candidate_pos`, `confidence`, `reason`。
3. 修改 `_try_recover_to_subpins()`：
   - 只用于跳到 SubPins，不应被记为 LinkedTo 成功。
   - 日志区分 `linkedto_recovered` 和 `subpins_resync`。
4. 新增测试覆盖：
   - 错误 count + 附近随机 0 不应恢复。
   - 错误 count + 合法 PinReference 应恢复。
   - negative count 回退后 archive 位置正确。

**验收:**

- LinkedTo 恢复成功率和误判率都有日志统计。
- 当前 24 条 LinkedTo refs 不下降，且失败原因更明确。

## Wave 3: 修复 Pin 序列化字段边界

**目标:** 基于 Wave 0-2 的证据，修正第一个真实错位字段。

**候选修复点:**

1. PinFriendlyName FText 是否总是存在。
2. SourceIndex 在当前 UE5 资产中是否始终存在。
3. PinType 后是否有 UE5 版本条件字段未处理。
4. DefaultValue / AutogeneratedDefaultValue 是否应区分 FString/FName 或 float 默认值格式。
5. DefaultObject 后 DefaultTextValue 是否存在版本条件。

**改动范围:**

- `src/uasset_read/serializers/graph.py`
- `tests/test_phase73_pin_layout.py`

**任务:**

1. 从失败 Pin 和成功 Pin 各选 3 个，生成字段边界对比表。
2. 结合 UE 编辑器导出文本，确认每个 Pin 的 LinkedTo 期望数量。
3. 对第一个错位字段添加版本条件或格式分支。
4. 把修复沉淀为回归测试，而不是只依赖样本资产集成测试。

**验收:**

- EventGraph LinkedTo refs 明显提升。
- `read_fstring()` 的 all-null / truncated 日志显著下降。
- `phase73_pin_trace.py` 显示失败 Pin 的错位位置后移或消失。

## Wave 4: PropertyTag 级联问题分流

**目标:** 将 Pin 边界修复后仍存在的 NodeComment、Transform、CharacterMovement 缺失归类，避免和 Pin 问题混在一起。

**改动范围:**

- `src/uasset_read/serializers/property_tags.py`
- `src/uasset_read/parsers/property_types.py`
- `tests/test_phase73_property_resync.py`

**任务:**

1. 对 `BodyInstance`、`SCS_Node.CategoryName`、`NodeComment` 添加 PropertyTag offset 追踪。
2. 找到第一个 `size` 或 `type` 不可信的 PropertyTag。
3. 如果是已知复杂 StructProperty，增加“按 tag.size 对齐到 value_end”的失败恢复。
4. 如果是 FName/FString 区分问题，补充专用读取路径，不改 `read_fstring()` 语义。

**验收:**

- PropertyTag 失败不会污染后续 Export 解析。
- NodeComment 和组件 Transform 问题有明确归类：已修复、单独 Phase、或格式未支持。

## Wave 5: 端到端连接输出验收

**目标:** 将恢复后的 `linked_to_raw` 变成可验证的 graph connections / execution flows / data flows。

**改动范围:**

- `src/uasset_read/graph/flow_builder.py`
- `src/uasset_read/formatters/json_formatter.py`
- `tests/test_phase73_bp_first_person_e2e.py`

**任务:**

1. 使用 `build_connections_map()` 对 4 个图分别统计连接。
2. 对照参考文档验证关键连接：
   - IA_Move / Primary Thumbstick -> Move
   - IA_Look / MouseLook / Secondary Thumbstick -> Aim
   - Jump start -> Jump
   - Jump end -> StopJumping
3. 将缺失连接输出为诊断表，而不是只断言数量。
4. 增加样本资产存在时运行的 integration test。

**验收:**

- EventGraph connections >= 9。
- Move/Aim 函数图存在可追踪执行链。
- 如果无法达到目标，报告列出每条缺失连接对应的 Pin 读取原因。

## 执行顺序

1. Wave 0 必须先执行，建立可重复诊断。
2. Wave 1 和 Wave 2 可顺序执行，先修消费语义，再修恢复误判。
3. Wave 3 只基于 Wave 0 的证据修改 Pin 布局。
4. Wave 4 独立分流 PropertyTag 问题，避免阻塞 Pin 连接恢复。
5. Wave 5 做端到端输出验收。

- 诊断脚本能解释每个 LinkedTo 失败点。

- Total LinkedTo refs 从 24 提升到 >= 40，或缺口有逐项解释。
- EventGraph connections >= 9。
- 新增测试覆盖核心二进制边界问题。
