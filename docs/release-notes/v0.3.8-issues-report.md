## 二、已知问题（未阻塞发布）

### 2.1 函数引用解析不完整

**严重程度**: 中
**影响范围**: 部分复杂蓝图（Lyra 等）

**现象**: 部分 `K2Node_CallFunction` 节点的 `function_reference` 为 `None` 或仅显示类路径，无法获取具体函数名。

```
🔹 /ShooterCore/Blueprint/B_ControlPointVolume.B_ControlPointVolume (K2Node_CallFunction_14)
🔹 None (Self)
🔹 ? (Self)
```

**影响资产**: B_Launcher、B_ControlPointVolume、GeneralAudioFunctions 等 Lyra 资产中出现。
**原因**: 复杂蓝图中的函数引用可能通过间接方式（如 Delegate、Interface）存储，当前解析器未完全覆盖。
**建议**: 0.3.9 版本优先处理。

### 2.2 变量名称解析缺失

**严重程度**: 低
**影响范围**: 所有蓝图

**现象**: Blueprint 变量名称显示为 `Unknown`，类型为 `FEdGraphPinType(pin_category='Warning')`。

```
Blueprint 变量: 4
  Unknown: type=FEdGraphPinType(pin_category='Warning', ...)
```

**原因**: 变量名提取逻辑未正确匹配某些变量描述格式。
**建议**: 检查 `BlueprintVariable` 模型的 name 属性映射。

### 2.3 Kismet 反编译属性访问

**严重程度**: 低
**影响范围**: 外部调用方

**现象**: `LinkerParseResult` 对象没有 `kismet` 属性，导致外部调用 `result.kismet` 抛出 `AttributeError`。

```python
AttributeError: 'LinkerParseResult' object has no attribute 'kismet'
```

**原因**: `kismet` 属性可能在某些解析路径下未被设置，或缺少 None 检查。
**建议**: 在 `LinkerParseResult` 中添加 `kismet: KismetDecompiledResult | None = None` 默认值。

### 2.4 未知 EExprToken 跳过

**严重程度**: 低（容错模式不中断）
**影响范围**: Kismet 字节码反编译

**现象**: 解析过程中出现大量 `Unknown EExprToken 0xFF at offset XXX, skipping in tolerant mode` 警告。

**影响**: 容错模式下跳过未知 token，部分函数体反编译不完整。
**建议**: 调查 `0xFF` token 在 UE 源码中的含义，补充到 `EExprToken` 枚举。

### 2.5 Cooked 资产无法解析图数据

**严重程度**: 预期行为（非 Bug）
**影响范围**: AnimBlueprint、部分 UMG Widget

**现象**: 部分资产解析成功但 Graphs 为空（0 节点）。

```
=== Lyra MM_Pistol_Jog_Right AnimBlueprint 分析 ===
解析成功: True
Graphs: 0
```

**原因**: 这些资产是 cooked 格式，图数据在烘焙时已被剥离。
**处理**: 这是预期行为，已在文档中明确说明。

### 2.6 PayloadTocOffset 负数处理

**严重程度**: 低
**影响范围**: 部分 IoStore/Pak 资产

**现象**: `PayloadTocOffset 为负数: -1, 设为 0`

**影响**: 容错处理自动修正为 0，但可能影响后续偏移计算。
**建议**: 确认 -1 是否为合法默认值，是否需要更精确的处理。
