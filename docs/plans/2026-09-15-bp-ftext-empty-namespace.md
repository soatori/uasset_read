# BP FText Empty-Namespace Recovery Tightening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop treating the valid empty-FText-namespace FString (`length=1` + single NUL) as `fstring_all_null` / `recovered_corruption`, so BP quality baselines can pin `recovered_corruption` to zero on tracked Blueprint seeds.

**Architecture:** One narrow change in `FArchive.read_fstring`: when UTF-8 `length == 1` and the payload is a single `0x00`, return `""` with a debug log only (no structured diagnostic). Longer all-null runs keep the existing `fstring_all_null` path. Regenerate `tests/samples/quality_baseline.json` so `BP_CombatCharacter.uasset` no longer allows `fstring_all_null/recovered_corruption`. No `format_version` bump; no reason-taxonomy change.

**Tech Stack:** Python 3.10+, stdlib, existing `uasset_read` package, pytest.

**Spec / evidence:**
- Root-cause write-up is this plan’s § Design brief.
- Quality follow-up row: `docs/plans/2026-09-15-parser-quality-system.md` (“BP/GA name_index root cause | recovered_corruption forbidden-list tightening”).
- Prior note that this pattern is valid UE data: `src/uasset_read/archive.py` `read_fstring` comment (#405).
- Live fixture: `tests/samples/BP_CombatCharacter.uasset` export:1 `NewVariables[].Category` FText (`namespace=""`, `key=<32-hex>`, `source_string="Damage"`).

## Global Constraints

- Python 3.10+; no new runtime dependencies.
- Library code returns structured diagnostics and does **not** configure process-global logging (`logger.debug` only).
- `format_version` stays `"2.0"`. Do **not** add/remove Diagnostic codes or reason enum values in this plan.
- Do not swallow longer all-null FStrings (length > 1) — those remain `fstring_all_null`.
- Do not change `read_name` / `name_index_out_of_range` behavior here.
- TDD: failing tests before implementation for each behavior-bearing task.
- Prefer editing existing files; no new package.
- Baseline file is generated by `tools/gen_quality_baseline.py` — edit the generator only if seed policy changes; otherwise regenerate.

## Design brief (source of truth for this plan)

### Measured current state (2026-09-15, `PYTHONPATH=src`)

| fixture | `fstring_all_null` | `name_index_out_of_range` |
|---------|-------------------:|--------------------------:|
| `BP_CombatCharacter.uasset` | 16 | 0 |
| `BP_CombatEnemy.uasset` | 12 | 0 |
| `LevelDesign_ABP_Manny.uasset` | 6 | 0 |
| `ALS_AnimBP.uasset` | 0 | 1 (index 2560, name table len 1582, export:281) |

`quality_baseline.json` currently allows `BP_CombatCharacter.uasset` → `fstring_all_null` / `recovered_corruption` max **16**.

### Root cause

All 16 CombatCharacter hits share this layout (serial region of export:1 `Blueprint` @ offset 453581, size 24455):

```
FText flags=0 (i32) + history_type=0 (Base)
FString namespace: length=1, payload=b"\x00"   ← read_fstring emits fstring_all_null
FString key:       length=33, "C159A931…042A" (32 hex + NUL)
FString source:    "Damage"
```

Parsed value (already correct):

```json
{"kind": "text", "namespace": "", "key": "C159A93144357F1B3CA9CBAE0457042A", "source_string": "Damage"}
```

This is the `Category` field of `BPVariableDescription` inside `NewVariables`. UE serializes an **empty ANSI/FText namespace as length=1 + NUL**, not length=0. `read_fstring` already returns `""` after `rstrip("\x00")` but still records a structured diagnostic with `reason="recovered_corruption"`, which pollutes the quality signal.

The historical BP/GA `name_index_out_of_range` cluster (external `BP_Player` sweep, indices ~1e9) is **not present** on tracked BP seeds. This plan does not chase `ALS_AnimBP`’s single moderate OOR index (2560).

### Success criteria

1. Unit: `ByteArchive(struct.pack("<i", 1) + b"\x00", tolerant=True).read_fstring() == ""` and **zero** structured diagnostics.
2. Unit: UTF-8 length=4 all-null still emits `fstring_all_null` (regression guard).
3. Integration: `parse_package_document(BP_CombatCharacter)` emits **0** `fstring_all_null`.
4. Same for `BP_CombatEnemy` and `LevelDesign_ABP_Manny` (assert 0, not just baseline-seed-only).
5. Regenerated baseline: BP seed has no `fstring_all_null` entry; gate still green.
6. `Category` values still `namespace=""` with non-empty `key` / `source_string`.

### Non-goals

- Fixing `ALS_AnimBP` `name_index_out_of_range` (residual; own follow-up if wanted).
- Changing FText history 1–10 decode.
- Changing reason taxonomy or adding a new diagnostic code.
- Zen / Niagara / RefSkeleton / DataTable work.

```python
def test_bp_seeds_have_zero_fstring_all_null():
    from pathlib import Path

    from uasset_read.package import parse_package_document

    samples = Path("tests/samples")
    names = (
        "BP_CombatCharacter.uasset",
        "BP_CombatEnemy.uasset",
        "LevelDesign_ABP_Manny.uasset",
    )
    for name in names:
        doc = parse_package_document(str(samples / name), depth="asset")
        codes = [d.code for d in doc.diagnostics]
        assert "fstring_all_null" not in codes, f"{name}: {codes.count('fstring_all_null')} fstring_all_null"


def test_bp_combat_character_category_text_still_decodes():
    from uasset_read.package import parse_package_document

    doc = parse_package_document("tests/samples/BP_CombatCharacter.uasset", depth="asset")
    export = next(o for o in doc.objects if o.id == "export:1")
    variables = (export.properties or {}).get("NewVariables") or []
    categories = []
    for entry in variables:
        if not isinstance(entry, dict):
            continue
        fields = entry.get("fields") or {}
        cat = fields.get("Category")
        if isinstance(cat, dict) and cat.get("kind") == "text":
            categories.append(cat)
    assert categories, "expected at least one FText Category on NewVariables"
    for cat in categories:
        assert cat.get("namespace") == ""
        assert cat.get("key"), cat
        assert cat.get("source_string"), cat
```
