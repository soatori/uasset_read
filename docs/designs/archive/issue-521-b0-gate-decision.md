## Source citations

1. **Pin storage.** `UNiagaraNode : public UEdGraphNode`
   (`Engine/Plugins/FX/Niagara/Source/NiagaraEditor/Public/NiagaraNode.h:28`). Niagara nodes
   declare no pin storage of their own; pins live in the inherited
   `TArray<UEdGraphPin*> Pins` member of `UEdGraphNode`
   (`Engine/Source/Runtime/Engine/Classes/EdGraph/EdGraphNode.h:293`). No Niagara node class
   overrides `Serialize` (verified across all NiagaraNode headers at the pinned commit; the
   fixture's node classes Reroute/Select/StaticSwitch/ParameterMapGet/ParameterMapSet are in
   `NiagaraEditor/Private/` in 5.8). All pin serialization is therefore the generic
   `UEdGraphNode`/`UEdGraphPin` path.
2. **Pin serialization.** `UEdGraphNode::Serialize`
   (`Engine/Source/Runtime/Engine/Private/EdGraph/EdGraphNode.cpp:212`) calls
   `UEdGraphPin::SerializeAsOwningNode(Ar, Pins)` at lines 258–261, guarded by
   `Ar.CustomVer(FBlueprintsObjectVersion::GUID) >= FBlueprintsObjectVersion::EdGraphPinOptimized`
   (enum value 4, `Engine/Source/Runtime/Core/Public/UObject/BlueprintsObjectVersion.h:17`).
   **Fixture `FBlueprintsObjectVersion` = 10 ≥ 4 → guard passes.** The whole block is
   `#if WITH_EDITOR` (EdGraphNode.cpp:214/232/262) and the friendly-name/editor tail fields are
   additionally `!Ar.IsFilterEditorOnly()` (EdGraphPin.cpp:1859/1895) — consistent with the
   project's editor-saved/unbaked-only scope; cooked packages would not carry this data.
   The path: `SerializeAsOwningNode` (`EdGraphPin.cpp:993`) → `SerializePinArray`
   (`EdGraphPin.cpp:2063`, writes `int32 ArrayNum` then per-pin `SerializePin`) →
   `SerializePin` (`EdGraphPin.cpp:2132`: `u32 bool bNullPtr`; when non-null
   `OwningNode` object reference + `FGuid PinId`, EdGraphPin.cpp:2136–2176) →
   for the owning-node resolve type, full pin body via `UEdGraphPin::Serialize`
   (`EdGraphPin.cpp:1838`, invoked at `EdGraphPin.cpp:2290`).
3. **LinkedTo boundary.** Serialized inside the pin body by
   `UEdGraphPin::SerializePinArray(Ar, LinkedTo, this, EPinResolveType::LinkedTo)`
   (`EdGraphPin.cpp:1886`). Each link entry is `{u32 bool bNullPtr, UObject* OwningNode
   (package index), FGuid PinGuid}` (EdGraphPin.cpp:2136–2176); on load it resolves against the
   owning node's `Pins` array by matching `PinId` (EdGraphPin.cpp:2193–2207). Edges are therefore
   package-internal, keyed by (owning node object reference, persistent pin GUID); `SubPins`
   (EdGraphPin.cpp:1889), `ParentPin` and `ReferencePassThroughConnection` (EdGraphPin.cpp:1891–1892)
   use the same reference form. Members: `LinkedTo`/`SubPins`/`ParentPin`/
   `ReferencePassThroughConnection` at `EdGraphPin.h:398/401/404/407`; `PinId` at `EdGraphPin.h:303`.

## Pin-record layout (byte-verified against the fixture)

`UEdGraphPin::Serialize` (EdGraphPin.cpp:1838–1948) writes, in order: `OwningNode` (object
reference), `PinId` (FGuid), `PinName` (FName, `FFrameworkObjectVersion::PinsStoreFName` = 30 ≤
fixture 37, EdGraphPin.cpp:1847–1856), `PinFriendlyName` (**FText**, EdGraphPin.h:373,
EdGraphPin.cpp:1861), `SourceIndex` (int32, EdGraphPin.cpp:1865–1868), `PinToolTip` (FString,
EdGraphPin.cpp:1870), `Direction` (u8, EdGraphPin.cpp:1871), `PinType`
(`FEdGraphPinType::Serialize`, EdGraphPin.cpp:163), `DefaultValue`, `AutogeneratedDefaultValue`
(FString), `DefaultObject` (object reference), `DefaultTextValue` (**FText**, EdGraphPin.h:395,
EdGraphPin.cpp:1876), `LinkedTo` / `SubPins` arrays, `ParentPin`,
`ReferencePassThroughConnection`, then the editor-only tail `PersistentGuid` (FGuid) + `BitField`
(u32) = 20 bytes (EdGraphPin.cpp:1894–1923). Booleans serialize as 32-bit (`Archive.h:1542–1548`,
"legacy, 32 bit int"). Before the pin array, `UObject::Serialize` writes the object-GUID presence
marker (§Unmapped regions, (a)).

## Disposition of the three unmapped regions from B0a

All three are **resolved with citations**:

(a) **Leading `int32 0` before the pin count** — the object-GUID presence marker.
`UObject::Serialize` calls `FLazyObjectPtr::PossiblySerializeObjectGuid` after the tagged
properties (`Engine/Source/Runtime/CoreUObject/Private/UObject/Obj.cpp:1859` properties,
`:1885` GUID marker); the marker is a structured-archive `TryEnterField` optional
(`Engine/Source/Runtime/CoreUObject/Private/UObject/LazyObjectPtr.cpp:116–141`), which in a binary
archive serializes a single bool (`Serialization/Formatters/BinaryArchiveFormatter.h:112–121`),
i.e. 4 bytes (`Archive.h:1542–1548`). All fixture exports write `false` → `00 00 00 00`.
This single field explains every observed tail shape: nodes (`0` + pin array),
NiagaraGraph/NiagaraScript/NiagaraScriptVariable (lone `0` = entire tail — no native fields),
EdGraphNode_Comment (`0` + pin count `0` = two zero int32s).

(b) **Region between `PinFriendlyName` and `PinType`** (B0a's "14-byte constant" vs
"`i32(256) + u16(0)` + 2 FStrings" variants) — standard fields mislabeled by the marker walk:
`PinFriendlyName` is an **FText**, not an FString. FText binary serialization is
`u32 Flags` + `i8 HistoryType` + history payload (`FText::SerializeText`,
`Engine/Source/Runtime/Core/Private/Internationalization/Text.cpp:888–988`; history enum
`ETextHistoryType::None = -1`, `Base = 0` in `Core/Private/Internationalization/TextHistory.h:24–27`).

- Plain pins: empty FText = `Flags(0)` + `HistoryType(0xFF)` + `u32 bool
  bHasCultureInvariantString(0)` (Text.cpp:978–987) = `00 00 00 00 ff 00 00 00 00` — the B0a
  "constant" bytes, minus the trailing `Direction` byte.
- Parameter/default-value pins: localized FText = `Flags(0)` + `HistoryType(0x00 = Base)` +
  `FTextHistory_Base` payload = `Namespace` + `Key` + `SourceString` FStrings
  (`TextHistory.cpp:810–911`). The 32-hex-digit string is the localization **Key**; the
  "pin name string" is the **SourceString**. B0a's `i32(256)` is `HistoryType(0)` +
  `Namespace length(1)`; the `u16(0)` is the empty-namespace terminator + high bytes.
After the FText: `SourceIndex` = `INDEX_NONE` (`ff ff ff ff`; EdGraphPin.cpp:1865–1868, default at
EdGraphPin.h:541), `PinToolTip` FString (empty on most pins), `Direction` u8, then `PinType`.

(c) **5-byte `ff 00 00 00 00` before non-empty `LinkedTo` counts** — the tail of the empty
`DefaultTextValue` FText (EdGraphPin.h:395, EdGraphPin.cpp:1876): `HistoryType(0xFF)` +
`u32 bool bHasCultureInvariantString(0)` (Text.cpp:978–987). The preceding `00 00 00 00` is the
FText `Flags`. It appears on every pin (B0a only flagged it before non-empty LinkedTo because the
walk used the LinkedTo count as its anchor).

## Byte-level verification (fixture anchor)

A field-level walk of **all 25** `NiagaraNode*` native tails using exactly the layout above
consumes **size/size bytes on every export** (no residual bytes anywhere): 99 pins total
(matching B0a's count 2+1+18+1+36+22+10+5+4), 76 `LinkedTo` edges, and **76/76 edges resolve**
to a pin GUID in the owning node's pin list (100%). Cross-checks: `OwningNode` back-references
equal each node's own PackageIndex; `PinSubCategoryObject` values resolve to the
`NiagaraParameterMap` (−26) / `NiagaraFloat` (−23) imports; `PinCategory` = name-table "Type";
B0a's four cross-verified connections reproduce (e.g. `NiagaraNodeSelect_1`'s input pin links to
node PackageIndex 8 = `NiagaraNodeOp_1`, whose `Result` pin GUID matches). The 20-byte editor-only
tail (`PersistentGuid` + `BitField`) lands exactly on each pin's final 20 bytes.

## Version deltas (fixture UE 5.0 vs checkout 5.8)

- **Guards that pass by number** (append-only streams stable across 5.0→5.8):
  `EdGraphPinOptimized` = 4 ≤ fixture 10 (pin path live); `PinsStoreFName` = 30 ≤ 37 and
  `EdGraphPinContainerType` = 25 ≤ 37 (`FrameworkObjectVersion.h:111/:95`);
  `PinTypeIncludesUObjectWrapperFlag` = 31 ≤ 44 (`ReleaseObjectVersion.h:110`).
- **`bSerializeAsSinglePrecisionFloat` absent from the fixture**: gated by
  `FUE5ReleaseStreamObjectVersion::SerializeFloatPinDefaultValuesAsSinglePrecision` = 36
  (`UObject/UE5ReleaseStreamObjectVersions.inl:118`, EdGraphPin.cpp:330–333) vs fixture
  UE5ReleaseStream = 33. Byte walk confirms: `DefaultValue` follows `bIsUObjectWrapper` directly.
  A 5.8-era package at stream ≥ 36 would carry one extra bool byte in `PinType`.
- **`SourceIndex` present in the fixture**: gated by
  `FUE5MainStreamObjectVersion::EdGraphPinSourceIndex` = 50
  (`UObject/UE5MainStreamObjectVersions.inl:161`). Numeric comparison of fixture UE5MainStream = 59
  against 5.8-numbered gates is not reliable on its own (5.8 defines these values explicitly via
  the `.inl`; the fixture is 5.0-era). Byte evidence is decisive: every pin carries
  `ff ff ff ff` (INDEX_NONE) between the `PinFriendlyName` FText and `PinToolTip`.
- `BlueprintPinsUseRealNumbers` = 29 ≤ 33 (`UE5ReleaseStreamObjectVersions.inl:97`,
  EdGraphPin.cpp:313–321): load-time category fixup only, no byte delta; fixture pins use the
  Niagara "Type" category and are unaffected.
- Code-organization delta: the fixture's Reroute/Select/StaticSwitch/ParameterMapGet/Set node
  classes live in `NiagaraEditor/Private/` in 5.8; none overrides `Serialize`, and the byte walk
  proves the generic path covers all 25 tails.
- FText shape (Flags + HistoryType + `bHasCultureInvariantString`), the object-GUID marker, and
  the 32-bit bools match the fixture bytes exactly (§Byte-level verification); where numbers and
  bytes could disagree, the byte walk wins.

## Gate decision

| Source says | Fixture says | Decision |
|---|---|---|
| serialized | markers found | **Pin path live** |

UE source shows pins are serialized (`UEdGraphNode::Serialize` →
`UEdGraphPin::SerializeAsOwningNode`, gated by `EdGraphPinOptimized`; fixture value 10 ≥ 4), and
the fixture contains them (B0a markers + full byte-level decode of all 25 tails, 99 pins, 76/76
edges resolved). Decision: **Pin path live** — no fixture expansion needed.
