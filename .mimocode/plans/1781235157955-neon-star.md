# Plan: Fix #130 — Blueprint / Graph Metadata 解析输出退化

## 问题概述

Blueprint 解析输出存在 3 个核心退化问题，导致 24 个测试失败。

## 根因分析

### 根因 A：Graph 检测失败（EventGraph/Move/UserConstructionScript 未被提取）

**文件**：`src/uasset_read/graph/parser.py` — `extract_blueprint_graphs()`

当前逻辑通过 `get_asset_class(export)` 检查 class_name 是否为 `EdGraph` 或 `UberEdGraph` 来识别 graph 导出。但对于 FirstPerson BP：
- Export 8（EventGraph）、9（Move）、10（UserConstructionScript）的 `class_index=-25` 解析为 import 24（`name=None, package=Class`），导致 `get_asset_class()` 返回 `None`
- 只有 Export 67（FirstPersonMesh_GEN_VARIABLE）和 68（CharacterMesh0）被正确检测为 `EdGraph`
- 实际 K2Node 导出（11-65）的 `outer_index` 指向 8/9/10，但这些父 graph 未被提取

**影响**：EventGraph 节点丢失 → function_graphs 为空 → blueprint_text 过短

### 根因 B：parent_class 解析为自身引用路径

**文件**：`src/uasset_read/blueprint/variable_extractor.py` — `extract_blueprint_metadata()` L800-840

Blueprint 导出（export 1）的 `ParentClass` ObjectProperty 解析结果为：
```python
{'type': 'import', 'object_name': '/Game/.../BP_FirstPersonCharacter_329', ...}
```
这是蓝图自身的 BPGC 引用，不是父类（`/Script/Engine.Character`）。

BPGC 的 `super_index=-23` 同样解析到 import 22（自身引用），而非真正的父类。

**根因**：linker 解析 `super_index` 时返回了错误的 import 条目。需要检查 linker 的 `resolve_package_index` 对于 BPGC super_index 的处理逻辑。

### 根因 C：AnimBlueprint blueprint = None

**文件**：`src/uasset_read/blueprint/variable_extractor.py`

AnimBlueprint（ABP_Manny_Combat）的 `result.blueprint is None`，说明 `extract_blueprint_metadata()` 未被调用或提前返回。

## 修复方案

### Fix 1：Graph 检测增加 fallback（根因 A）

**修改文件**：`src/uasset_read/graph/parser.py`

在 `extract_blueprint_graphs()` 中增加 fallback 逻辑：
1. 当 `get_asset_class()` 返回 None 时，检查 export 的 `object_name` 是否匹配已知 graph 名称模式（`EventGraph`、`Move`、`UserConstructionScript`、`AnimGraph` 等）
2. 或检查 export 是否有 K2Node 子导出（通过 outer_index 反向查找）

```python
# 在现有 EdGraph/UberEdGraph 检测之后，增加 fallback
if not is_graph and class_name is None:
    # Fallback: 按名称模式检测 graph 导出
    name = export.object_name or ""
    if name in ("EventGraph", "Move", "UserConstructionScript", "AnimGraph") or \
       name.endswith("_GEN_VARIABLE"):
        is_graph = True
```

### Fix 2：parent_class linker 解析修复（根因 B）

**修改文件**：`src/uasset_read/serializers/object_resources.py`

检查 `resolve_parent_class_with_linker()` 中 `linker.resolve_package_index()` 的行为。当 super_index 指向一个 `class_package` 与自身包路径匹配的 import 时，需要识别这是 self-reference 并尝试从其他来源（如 import 的 outer 链）查找真正的父类。

同时修改 `variable_extractor.py` 中 parent_class 提取逻辑：当 ObjectProperty 的 `object_name` 包含自身蓝图路径时，尝试通过 import 的 `class_name` 字段或 outer 链解析真正的父类。

### Fix 3：AnimBlueprint 蓝图检测（根因 C）

**修改文件**：`src/uasset_read/parse_uasset.py`

检查 `_post_process()` 中 blueprint metadata 提取的调用条件，确保 AnimBlueprint 导出也能触发 `extract_blueprint_metadata()`。

### Fix 4：blueprint_text 渲染修复

**修改文件**：`src/uasset_read/renderers/blueprint_text_renderer.py`

确保 blueprint_text 渲染器在有 graph 数据时输出 EventGraph 节点信息，而非仅输出 Package/Class 空壳。

## 关键文件
